# Arvix

Личный ИИ-ментор. Полная спецификация лежит в `docs/` — прочитай `docs/README.md`,
`docs/00-VISION.md` и `docs/01-ARCHITECTURE.md` перед началом работы, если ещё не читал их в этой сессии.

Мы работаем спринтами. Один шаг из `docs/09-PHASE-0-1-PLAN.md` = один запрос = один коммит.
Не забегай вперёд по плану и не делай больше одного шага за раз, даже если следующий шаг кажется очевидным.

## Незыблемые правила

1. Всё, что можно сделать кодом — делается кодом. ИИ (LLM-вызов) только там, где нужно
   понимание естественного языка или суждение. Начисление XP, снятие HP, отправка
   напоминаний, переключение режима — детерминированный Python-код, никогда не модель.
2. Совет моделей (L2) никогда не стоит в цепочке ответа пользователю. Он работает в фоне
   по расписанию/триггерам и пишет директивы в БД. Ответ в чате всегда даёт L1 — один вызов.
3. Любое изменение состояния идёт через запись события в таблицу `events`. Прямой UPDATE
   проекций (`state_daily`, `state_current`, `state_weekly`) запрещён — только пересчёт из лога.
4. Имена LLM-моделей никогда не хардкодятся в коде — только в конфиге ролей (`roles.yaml`).
5. В режиме Burnout Guard = RED и при `mentor_enabled = false` жёсткие тон-блоки физически
   не должны попадать в промпт. Это утверждение проверяется юнит-тестом, а не обещанием в тексте.
6. Один пользователь (single-user). Никакой мультитенантности, ролей доступа, биллинга,
   регистрации.

## Как работать

- Перед шагом: прочитай соответствующий раздел в `docs/`, если контекст не свежий.
- После шага: прогони тесты и покажи, что реально работает (команда/curl/скриншот — что уместно).
- Не переходи к следующему шагу без явного разрешения — жди ревью диффа.
- Если по ходу работы находишь противоречие или дыру в спецификации — останавливайся и спрашивай,
  не додумывай молча.

## Команды
- `make up` — поднять всё через `docker compose up -d --build`
- `make down` — остановить
- `make logs` — логи `core`
- `make migrate` — применить миграции (`alembic upgrade head`)
- `make revision m="сообщение"` — новая миграция
- `make lint` — `ruff check core`
- `make test` — `pytest`

Локальная проверка без Docker: `.env` из `.env.example` (не коммитится), затем
`pip install -e .` и `uvicorn core.main:app --reload` — но основной путь именно через Docker Compose.
