# Arvix

Личный ИИ-ментор одного человека. Продукт — `arvix-claude/` (чистый Python 3.11+, без зависимостей): ядро `arvix/`,
плагин Claude Code, Telegram-бот, CLI. Спецификация — `docs/`: перед работой прочитай `docs/README.md`,
`docs/00-VISION.md` и `docs/01-ARCHITECTURE.md`, если ещё не читал их в этой сессии, плюс профильный документ задачи.
`archive/v1-docker/` — старый прототип, его не трогать и не запускать.

## Незыблемые правила

1. Всё, что можно сделать кодом, делается кодом. Модель — только там, где нужно понимание языка или суждение.
   XP, HP, долг, режим, напоминания, нагрузка — детерминированный Python (`rules.py`, `daily.py`, `load.py`, `telegram/scheduler.py`).
2. Совет (L2) никогда не стоит в цепочке ответа. Ответ в чате — один вызов L1.
3. Любое изменение состояния — событие через `Core.emit()` внутри `Core.tx()`. UPDATE и DELETE таблицы `events`
   запрещены триггерами; исправление — компенсирующее событие. Состояние — свёртка журнала (`state.py`).
4. Имена моделей — только в `arvix/defaults.toml` и конфиге пользователя (`[roles.*]`). В коде их нет — это тест.
5. В 🟥 и при выключенном менторе жёсткие тон-блоки, жёсткие примеры и `decision_rule` физически не попадают в промпт.
   Это проверяет `tests/test_prompt_safety.py`, а не обещание в тексте.
6. Один человек: бот отвечает только `owner_id`. Никакой мультитенантности, ролей, регистрации, биллинга.

Плюс фильтр из `docs/00-VISION.md §6`: фича, не прошедшая пять вопросов, не делается.

## Как работать

- Задачи берутся из `docs/08-ROADMAP.md`. Один пункт = одна ветка = один PR. Не забегай к следующему пункту.
- Каждое изменение поведения — с тестом, который падает на прежнем коде, и с правкой спецификации в том же PR:
  документ, расходящийся с кодом, хуже его отсутствия. Решение, меняющее принцип, — строкой в `docs/09-DECISIONS.md`.
- Правишь `arvix/constitution/*` — пересобери `python3 scripts/build_assets.py`: стиль и файлы claude.ai генерируются,
  тест следит, что они не устарели.
- Нашёл противоречие или дыру в спецификации — запиши в `docs/09-DECISIONS.md` §6 «Открытые вопросы» и спроси
  владельца, если от ответа зависит, что строить.
- Коммит и пуш — только когда владелец попросил. Секреты (`~/.config/arvix/config.toml`, `claude.env`, `.env`) в git не попадают.
- Деплой (`deploy/install.sh`, `deploy/sync-server.sh`) перезапускает живого бота — только после мержа и с согласия владельца.

## Команды

Из `arvix-claude/`:
- `python3 -m unittest discover -s tests -t .` — все тесты, без сети и без ИИ
- `python3 -W error::ResourceWarning -m unittest discover -s tests -t .` — то же, строже
- `python3 scripts/build_assets.py [--check]` — пересобрать или проверить сгенерированные файлы
- `claude plugin validate .` — манифест, хуки, MCP
- `bash deploy/install.sh` — выкатить на эту машину; `bash deploy/sync-server.sh arvix@HOST` — на сервер

Проверка поведения без Telegram — CLI на временной базе:
`ARVIX_LOCAL=1 ARVIX_DATA_DIR=/tmp/a ARVIX_CONFIG_DIR=/tmp/c python3 scripts/arvix_cli.py status`.
