# Цели

Цель без цепочки до сегодняшней задачи — мечта. Задача без цели — псевдопродуктивность.
Этот скилл строит цепочку: **цель → этапы → роадмап → блоки в плане → проверка**.

## Новая цель
1. `profile` action=goals — что уже есть. Новая цель не должна дублировать или противоречить
   старой; если противоречит — скажи прямо и спроси, какую оставить (старую — status=dropped).
2. Сделай цель проверяемой, без воды. Нужны:
   - **результат** — что именно будет («оффер на позицию фронтенд-джуна», а не «стать программистом»);
   - **метрика** — как проверить;
   - **дедлайн** — дата;
   - **зачем** — своими словами человека. Без «зачем» цель не записывается: на нём держится
     мотивация в плохие дни.
   Размыто — один уточняющий вопрос за раз.
3. Реальность: сколько часов в неделю есть (бюджет из контекста), что уже умеет, что мешало
   раньше (черты и триггеры из контекста). Цель не влезает — скажи цифрой: «Нужно ~300 часов,
   у тебя 8 ч глубокой в неделю — это 37 недель, а до дедлайна 20. Сдвигаем срок или сужаем
   цель?»
4. Запиши: `profile` action=goal (title, why, metric, deadline, kind: main | yearly | quarterly).

## Этапы
5. Разбей на 3–7 этапов, каждый на 2–6 недель, каждый с проверяемым результатом и датой:
   «к 15.12 — 3 своих компонента на React в GitHub», а не «изучить React».
6. Покажи таблицей, после «да» запиши каждый этап: `profile` action=goal с parent_id = id цели,
   kind=milestone, deadline, metric (why для этапа не обязателен).
7. Если цель учебная — для ближайшего этапа роадмап по правилам скилла `learn`
   (`Arvix/Roadmaps/<Название>.md`: узлы, первоисточники, часы, чекпоинты).
8. Ближайший этап — в план: через скилл `plan` или сразу шаблоном —
   `profile` action=template, блоки глубокой работы в часы пика энергии.
9. Запиши файл цели `Arvix/Goals/<Название>.md` (`notes` action=write): цель, зачем, метрика,
   этапы с датами чеклистом, ссылка на роадмап.

## Проверка прогресса («как я иду к цели?»)
1. `profile` action=goals + `analyst` action=events days=14 — что реально сделано по этапу:
   задачи этой сферы, часы глубокой работы, отчёты.
2. Ответ цифрами: этап X, дедлайн через N дней, сделано Y из Z, темп — успеваешь или нет.
   Не успеваешь — одно решение: добавить часы (откуда именно), сузить этап или сдвинуть дату.
   Решает человек.
3. Этап пройден — проверь результат по метрике (покажи, сдай чекпоинт). Только потом
   `profile` action=goal goal_id=<этап> status=done и обнови чеклист в `Arvix/Goals/…`.
   «Почти сделал» — не done.
4. Цель потеряла смысл — это нормально. status=dropped с причиной, без морали.

## Регулярность
- Каждое воскресенье `retro` смотрит темп по текущему этапу.
- Раз в месяц — пересмотр: цель всё ещё твоя? Зачем всё ещё правда?
