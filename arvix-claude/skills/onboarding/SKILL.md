# Знакомство и настройка

Итог — система, которая реально ведёт к целям:
- профиль;
- распорядок дня, из которого каждое утро появляются задачи с напоминаниями;
- цели с этапами;
- роадмапы по главным предметам;
- ежедневный отчёт;
- нагрузка, которая растёт без выгорания.

Идём по шагам 0–7, после каждого шага коротко показывай, что записано, и спрашивай, дальше или пауза. Пауза — нормально: всё сохраняется, продолжение с того же места.

## 0. Прочитать хранилище целиком (до вопросов)
1. `notes` action=overview — карта: папки, все заметки, места для файлов Арвикса.
2. Прочитай (`notes` action=read) всё, что говорит о человеке и его системе. В этом хранилище это, как правило:
   - `05_System/*` — цели, распорядок, «как я учусь», недели;
   - `03_Resources/Обучение/*` — **его собственные методы обучения**: Фейнман, универсальный метод, как отдыхать;
   - `02_Areas/*/00_*.md` — карты предметов;
   - `02_Areas/Подготовка к ОГЭ/*` — расписание экзаменов;
   - `01_Projects/*` — проекты;
   - последние отчёты в папке ежедневных заметок и шаблон отчёта.
   Заметок мало (десятки) — читай полностью, не по одной строке.
3. `interview` action=status и `context` — что уже известно.
4. Сводка человеку в 8–12 строк: что ты о нём уже знаешь, какой у него метод обучения, какие цели и предметы. Отдельно — где противоречия или пробелы, например «цель — ОГЭ, но роадмапа по математике нет».

## 1. Оставшиеся вопросы
- Бери вопросы из `interview` action=next (id в квадратных скобках), блоками по 3–4 в одном сообщении.
- Ответ уже есть в заметках или в профиле — не спрашивай заново, а подтверди: «В заметках подъём 7:00 — это ещё так?». Подтверждение сохрани как ответ (`interview` action=answer).
- Размытый ответ — один конкретный уточняющий вопрос. «Нормально», «по-разному», «как обычно» не принимай.
- Не хочет отвечать — `interview` action=skip.
- Испорченный или устаревший ответ — `interview` action=reset qid=… и спроси снова.
- После каждого блока разложи ответы:
  - цели → `profile` action=goal;
  - привычки, триггеры, слабости, страхи → `profile` action=trait;
  - факты → `profile` action=remember;
  - поля вроде класса, экзаменов, вуза → `profile` action=set.

## 2. Распорядок дня → шаблоны
По блокам «Ядро», «Учёба», «Распорядок дня» и «Тело» собери шаблоны дней. Правила:
- **Бюджет** — строка НАГРУЗКА в `context` (стартует с ответа «сколько часов готов учиться»). Сумма блоков за неделю не больше бюджета. Начинаем с того, что точно потянет, а не с героизма.
- Блоки только в свободных окнах:
  - первый — через 30+ минут после школы или работы;
  - последний заканчивается за час до отбоя;
  - глубокая работа — в пики энергии (у человека — утро и вечер, днём после еды спад).
- 1–3 блока в будний день. Работа, тренировки и репетиторы — с реальным временем. Один восстановительный день без учёбы.
- Названия конкретные: «Математика ОГЭ: задания 1–5», а не «Учёба». Важность 4–5 — только главному.

Покажи таблицей, дождись «да» или правок, затем `profile` action=template для каждой группы дней. Без шаблонов нет задач и напоминаний — если человек хочет пропустить шаг, скажи это прямо.

## 3. Цели — по скиллу `goal`
- Разведи **мечты** (Stanford, своя компания, блог) и **цели на год** (ОГЭ, английский, привычки).
- Мечта — kind=dream, без дедлайна. Цель — проверяемая: результат, метрика, дата, «зачем».
- Размытая цель вроде «обрести кучу полезных привычек» разбивается на 2–4 конкретных с метриками. Старую — status=dropped, с объяснением.
- Этапы с датами (parent_id), ближайший этап — в распорядок.

## 4. Роадмапы — по скиллу `learn`
- Для каждой учебной цели и главного предмета — роадмап, построенный **по методу человека** из его заметок (Фейнман → чекпоинт «объясни своими словами»).
- Есть папка предмета (`02_Areas/<Предмет>/`) — роадмап туда; ссылку на него допиши в карту предмета `00_<Предмет>.md` (append). Нет — `notes` kind=roadmaps.
- Ближайший узел каждого роадмапа — блок в распорядке.

## 5. Ежедневный отчёт
1. Прочитай шаблон отчёта (путь — в `.obsidian/daily-notes.json`; `notes` action=daily_sync создаёт отчёт дня по этому шаблону).
2. Предложи улучшения под то, что реально помогает: какие поля Арвикс заполнит сам (сон, подъём, фокус, тренировка), какие — человек (телефон, игры, срывы, вывод дня), чего не хватает (например, «энергия 1–5» или «главное дело дня»).
3. Шаблон — заметка человека. Перезаписывать только после явного «да» (`notes` action=write path=<шаблон> force=true); бэкап сделается сам.
4. Объясни, как это работает дальше:
   - утром бот создаёт отчёт с задачами;
   - вечером после разбора вписывает итоги в свой блок;
   - пустые поля заполняет сам, твой текст не трогает.

## 6. Нагрузка без выгорания (автонагрузка)
Человек не задаёт часы — объём решает код (`arvix/load.py`). Не спрашивай «сколько часов в фокусе».
- В шаблонах обязательное (школа, дорога, репетитор, секция) — `fixed: true`: его объём не меняется никогда.
  Самостоятельная учёба, глубокая работа, спорт, отдых — без fixed: их длительность масштабирует код.
- Покажи строку НАГРУЗКА: «авто: глубокая работа …, учёба …, спорт …, отдых …».
- Объясни правила в 4 строках:
  - старт — 70% от названного: люди переоценивают силы;
  - раз в неделю код смотрит выполнение по каждому каналу, сон, HP, дни 🟨/🟥;
  - признаки выгорания — сразу −20% работы и +20% отдыха; рост +10% — только после двух ровных недель ≥ 85%;
  - перемены приходят одной строкой в утреннем брифинге с причиной.

## 7. Финал
- `export` — профиль, цели и выводы попадут в хранилище, в блоки Арвикса.
- Итог в 6 строках: мечта → цель года → ближайший этап; распорядок; главный риск (у человека: думскроллинг и CS2 при отсутствии цели) и что Арвикс делает, когда риск срабатывает; бюджет нагрузки.
- Напомни: Telegram ведёт день (брифинг, напоминания, разбор), Claude Code — для планов, целей и учёбы.
