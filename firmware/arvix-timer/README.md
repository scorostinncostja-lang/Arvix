# Arvix Timer — прошивка ESP32

Тонкий клиент фокус-сессий. Полная инженерная спецификация (BOM, схема,
распиновка, питание, корпус) — в `../../docs/10-ESP32-BUILD.md`.
Протокол WebSocket — в `../../docs/06-IOT-BIOMETRICS.md`.

## Структура

```
include/
  config.h          — пины, дефолты сети, таймауты (правь тут, не в .cpp)
  types.h           — Phase enum, DeviceState, PendingEvent
  display_ctl.h
  led_ctl.h
  buzzer_ctl.h
  keypad_ctl.h
  offline_buffer.h  — NVS-буфер событий на случай обрыва связи
  net_client.h       — WiFiManager + WebSocket
src/
  *.cpp              — реализации, один файл на модуль, main.cpp — стейт-машина
```

Модули не знают друг о друге напрямую — `main.cpp` — единственное место,
где связаны клавиатура, сеть, экран и локальный таймер. Если нужно
поменять поведение клавиши — правится `handleKey()` в `main.cpp`, а не
`keypad_ctl.cpp` (там только опрос матрицы).

## Сборка и прошивка (PlatformIO)

```bash
# Установка PlatformIO (если ещё нет)
pip install --user platformio

# Из папки firmware/arvix-timer/
pio run                  # сборка
pio run -t upload        # прошивка (подключи ESP32 по USB-C)
pio device monitor       # Serial-монитор, 115200 бод
```

В VS Code — расширение **PlatformIO IDE**, открыть папку `arvix-timer/` как проект.

## Первое включение

1. При первом старте (нет сохранённого Wi-Fi) устройство поднимает точку
   доступа **`Arvix-Setup`**.
2. Подключиться к ней телефоном/ноутбуком, откроется портал `192.168.4.1`
   (или откроется автоматически — captive portal).
3. Ввести обычный Wi-Fi (SSID/пароль) + два кастомных поля:
   - **Сервер (host)** — домен, на котором крутится `arvix-core`
   - **Токен устройства** — генерируется в TWA (Настройки → IoT → Новое устройство), одноразовый UUID
4. Устройство перезагрузится и подключится к серверу по `wss://<host>/ws/device`.

**Сброс сети:** зажать кнопку СТОП при включении — устройство сотрёт
сохранённые настройки Wi-Fi и снова поднимет портал.

## Тестирование модулей по отдельности

Перед сборкой в корпус — раскомментировать нужный блок в `main.cpp` или
временно залить упрощённый скетч. Минимальный чек — см.
`docs/10-ESP32-BUILD.md` §8 (чек-лист бринг-апа).

Быстрая проверка I2C-адреса дисплея (если OLED не находится):
```cpp
// временно в setup(), после Wire.begin(OLED_SDA, OLED_SCL):
for (byte addr = 1; addr < 127; addr++) {
    Wire.beginTransmission(addr);
    if (Wire.endTransmission() == 0) Serial.printf("I2C device: 0x%02X\n", addr);
}
```

## Что сервер должен уметь принять (эндпоинт `/ws/device`)

Смотри `docs/06-IOT-BIOMETRICS.md` — раздел "Протокол". Прошивка шлёт
`hello`, `session_start`, `session_end`, `key`, `heartbeat`; ждёт от
сервера `state` (полное состояние для отрисовки) и `beep` (паттерн звука).
Если сервер присылает `{"replay": true}`-события из буфера — это флаг,
что таймстамп `at` не "сейчас", а исторический (событие копилось офлайн);
без этого флага сервер обрабатывает `at` как реальное время получения.

## Известные ограничения текущей версии (осознанно, не забыто)

- Не реализована OTA-прошивка по воздуху — обновления только по USB.
  При одном устройстве это не проблема; если станет неудобно — `ArduinoOTA`
  подключается одним модулем, схема это не ломает.
- `WebSocketsClient::beginSSL` использует системные корневые сертификаты
  библиотеки; если сервер на самоподписанном сертификате — нужно либо
  указать `setCACert()`, либо (для домашнего прототипа) использовать
  `ws://` без TLS во внутренней сети и переключить на `wss://` при выходе
  в публичный интернет. Правится в `net_client.cpp`, `net_client::begin()`.
- Локальный таймер в офлайне не учитывает Burnout Guard/сон — это осознанно:
  устройство не принимает решений, оно просто не даёт блоку "зависнуть"
  молча до восстановления связи с сервером.
