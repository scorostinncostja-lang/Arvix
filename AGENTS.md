# AGENTS.md — общие правила для Codex и Claude Code в репозитории Arvix

Единственный свод правил для **обоих** агентов. Codex читает этот файл сам, Claude Code подключает его из
[CLAUDE.md](CLAUDE.md) (`@AGENTS.md`). Правило меняется только здесь: копий нет, расходиться нечему.

Рядом ещё два общих файла:
- [ARCHITECTURE.md](ARCHITECTURE.md) — карта кода: модули, процессы, путь сообщения, инварианты, рецепты изменений;
- [PLANS.md](PLANS.md) — как писать план большой задачи, чтобы её мог продолжить любой из агентов.

Владелец — один человек, школьник, пишет по-русски. Отвечай по-русски, коротко, без воды, с конкретными командами.
Сложное объясняй шагами «что делаем → почему так → какой результат».

## 1. Кто есть кто

| | Claude Code | Codex (ChatGPT) |
|---|---|---|
| Где работает | ноутбук владельца, рабочие копии `.claude/worktrees/<имя>/` | облако или папка репозитория |
| Ветки | `claude/<тема>` | `codex/<тема>` |
| Свои правила сверх этого файла | `CLAUDE.md` (только специфика Claude Code) | нет |
| Сервер и деплой | по явному «да» владельца после мержа (§8) | нет доступа и не должно быть |

Оба агента равны: никто не правит чужую открытую ветку без просьбы владельца. Продолжить чужую задачу —
можно, если владелец попросил: сначала прочитай её план (`plans/…`, см. [PLANS.md](PLANS.md)) и PR.

## 2. Что такое Arvix

Личный ИИ-ментор **одного** человека. Знает план дня и цели, сам напоминает в Telegram, спрашивает результат,
считает долг и режим нагрузки кодом, вечером проводит разбор, раз в неделю — ретро. Данные человека — в его
Obsidian. Голова — `claude -p` по подписке Claude (без API-ключей). С D62 Arvix — **навигатор по инструментам
человека** (Решу ОГЭ, ФИПИ, Anki, NotebookLM…): даёт шаги «сделай → в каком инструменте → сколько минут»,
а не строит свои аналоги.

Продукт — `arvix-claude/`: чистый Python 3.11+ без зависимостей. Пять лиц на одном ядре и одной базе:
Telegram-бот, приложение (Mini App / PWA), плагин Claude Code, чат Claude Desktop (MCP), CLI `arvix`.
Три слоя: **L0** — рефлексы, Python без модели; **L1** — голос, один вызов модели на сообщение,
модель возвращает `{reply, actions}`, actions исполняет код; **L2** — совет (разбор, ретро), только в фоне.
Подробно — [ARCHITECTURE.md](ARCHITECTURE.md).

## 4. Незыблемые правила (нарушение = PR не принимается)

1. **Всё, что можно сделать кодом, делается кодом.** Модель — только где нужно понимание языка или суждение.
   Долг, режим, напоминания, нагрузка — детерминированный Python (`rules.py`, `daily.py`, `load.py`,
   `telegram/scheduler.py`). Игры нет: ни XP, ни HP, ни уровней, ни серий (D41) — только факты из журнала.
2. **L2 никогда не стоит в цепочке ответа.** Ответ в чате — один вызов L1.
3. **Любое изменение состояния — событие через `Core.emit()` внутри `Core.tx()`.** UPDATE и DELETE таблицы `events`
   запрещены триггерами; исправление — компенсирующее событие. Состояние — свёртка журнала (`state.py`).
   Новый тип события — в каталог `docs/03-DATA-MODEL.md` и в свёртку.
4. **Имена моделей — только в `arvix/defaults.toml` и конфиге пользователя** (`[roles.*]`). В коде их нет — это тест.
5. **В 🟥 и при выключенном менторе** жёсткие тон-блоки, жёсткие примеры и `decision_rule` физически не попадают
   в промпт. Это проверяет `tests/test_prompt_safety.py`, а не обещание в тексте.
6. **Один человек.** Бот отвечает только `owner_id`. Никакой мультитенантности, ролей, регистрации, биллинга.
7. **Без зависимостей.** Только стандартная библиотека Python. Нет Docker, Postgres, Redis, очередей, WebSocket,
   векторной БД, нескольких LLM-провайдеров (см. «Чего не будет» в `docs/08-ROADMAP.md`).
8. **Фильтр пяти вопросов** из `docs/00-VISION.md §6`: фича, не прошедшая его, не делается — скажи владельцу прямо.

## 5. Как работать

- Задача = один пункт `docs/08-ROADMAP.md` или явная просьба владельца. Один пункт = одна ветка = один PR.
  Не забегай к следующему пункту и не «улучшай заодно».
- Ветка — от свежего `origin/main`, префикс своего агента (§1). Перед началом: `git fetch` и открытые PR
  другого агента. Горячие файлы — `telegram/bot.py`, `core.py`, `web/static/app.js`: если их уже меняет чужая
  ветка, скажи владельцу до начала работы.
- Большая задача (больше одной сессии, больше трёх модулей, новое событие или решение `D<N>`) — сначала план
  по [PLANS.md](PLANS.md), потом код.
- Каждое изменение поведения — **с тестом, который падает на прежнем коде**, и с правкой спецификации в том же PR.
  Документ, расходящийся с кодом, хуже его отсутствия. Поменял карту кода — обнови `ARCHITECTURE.md`.
- **Видимое человеку проверяй как человек**, а не только тестом: CLI на временной базе, приложение в браузере,
  путь в Telegram по шагам. В описании PR — что именно прошёл руками и что не смог проверить.
- Решение, меняющее принцип, — строкой `D<N>` в `docs/09-DECISIONS.md` §2. Номер — следующий после последнего
  **в `origin/main`**, а не в своей ветке (оба агента занимают номера, коллизии уже были):
  `git fetch && git show origin/main:docs/09-DECISIONS.md | grep -o 'D[0-9]\+' | sort -V | tail -1`.
- Нашёл противоречие или дыру в спецификации — запиши в `docs/09-DECISIONS.md` §6 «Открытые вопросы» и спроси
  владельца, если от ответа зависит, что строить.
- Правил `arvix/constitution/*` — пересобери `python3 scripts/build_assets.py`: стиль и файлы claude.ai
  генерируются, тест следит, что они не устарели.
- Правил `arvix/web/static/*` — подними версию кэша `CACHE = "arvix-vNN"` в `sw.js`, иначе телефон покажет старую
  оболочку. Все `:hover` в `app.css` — только в блоке `(min-width: 900px) and (hover: hover)` (есть тест).
- Коммит, пуш, PR — только когда владелец попросил. В конце коммита — строка `Co-Authored-By` своего агента.
- Секреты в git не попадают: `~/.config/arvix/config.toml`, `claude.env`, `.env`, токены, ключи голоса, адрес сервера.
  Репозиторий **публичный**.

## 6. Команды (из `arvix-claude/`)

```bash
python3 -m unittest discover -s tests -t .                          # все тесты, без сети и ИИ (~35 с)
python3 -W error::ResourceWarning -m unittest discover -s tests -t . # строже — так проверяй перед PR
python3 -m unittest tests.test_rules -v                              # один модуль
python3 scripts/build_assets.py --check                              # сгенерированные файлы не устарели
claude plugin validate .                                             # манифест, хуки, MCP (если есть claude CLI)
```

Проверка поведения без Telegram и без настоящих данных — CLI на временной базе:
```bash
ARVIX_LOCAL=1 ARVIX_DATA_DIR=/tmp/a ARVIX_CONFIG_DIR=/tmp/c python3 scripts/arvix_cli.py status
```

Никогда не запускай тесты или CLI против настоящей базы `~/.local/share/arvix/arvix.db`.

## 7. Где что живёт на машинах владельца (для понимания, не для правки)

| Что | Где |
|---|---|
| Журнал событий (источник правды) | сервер: `~/.local/share/arvix/arvix.db` (SQLite, WAL) |
| Конфиг и токен бота | `~/.config/arvix/config.toml`, права 600 |
| Вход в Claude для головы на сервере | `~/.config/arvix/claude.env`, права 600 |
| Установленная копия плагина | `~/.local/share/arvix/app` (её ставит `deploy/install.sh`) |
| Хранилище Obsidian | ноутбук ↔ сервер `~/vault`, `rsync` раз в 2 мин |
| Бэкапы журнала | ноутбук: `~/.local/share/arvix/backups/` (каждый час, 30 дней) |

Бот, приложение и журнал — на VPS под пользователем `arvix` (Ubuntu 24.04, systemd --user).
Ноутбук (CachyOS) — в удалённом режиме: `[remote] host` в конфиге, MCP/CLI/хук ходят на сервер по SSH.
Приложение снаружи — Caddy, `https://<ip-через-дефисы>.sslip.io:8443`.

## 8. Деплой — только с явного «да» владельца

Деплой перезапускает живого бота. Только после мержа PR и с явного «да» владельца в этом же разговоре:
```bash
bash arvix-claude/deploy/install.sh                 # ноутбук
bash arvix-claude/deploy/sync-server.sh arvix@HOST  # сервер: код → install.sh → рестарт бота
```
Codex не подключается к серверу и не читает его конфиг. Никто не трогает `deploy/restore-server.sh` без задачи.

## 9. Чего не делать

- Не возвращать то, что убрано решениями: XP/HP/уровни (D41), вкладки «Проекты» и «Обучение» (D62), звонок (D52),
  пузырьки сообщений (D46), свои тесты/плееры/карточки вместо инструментов человека (D62).
- Не строить платформу агентов, мультимодельный совет, Android-проект, TWA, вебхуки.
- Не обходить ограничения YouTube (PO-токен) для субтитров — решено не делать.
- Не дописывать фичи без недели реального использования предыдущих: правило `docs/08-ROADMAP.md` «польза раньше фич».
