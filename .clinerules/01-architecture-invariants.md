# Архитектурные инварианты Arvix (НЕЗЫБЛЕМЫЕ ПРАВИЛА)

1. **Разделение L0 / L1 / L2**:
   - L0 (Рефлексы) — чистый детерминированный Python-код без ИИ (таймеры, напоминания, расчет XP/HP, Burnout Guard, квоты). Если задачу можно решить формулой или шаблоном — ИИ не вызывается.
   - L1 (Голос) — быстрый ответ пользователю (<1.5 сек), максимум 1–2 итерации вызова инструментов (tools). Никогда не считает XP/HP сам — только вызывает tools из L0.
   - L2 (Совет) — тяжелая аналитика (Analyst, Planner, Chief), работает СТРОГО в фоне/воркере, никогда не блокирует ответ пользователю в чате. Пишет результат в таблицу `directives`.
2. **Event Sourcing / Append-only Log**:
   - Любое изменение бизнес-состояния ОБЯЗАНО проходить через `core/events/log.py -> emit()`.
   - Запрещено делать прямые `UPDATE` в таблицы проекций (`state_current`, `state_daily`, `state_weekly`) в обход `projections.py`.
3. **Универсальный AI-клиент (OpenAI-compatible)**:
   - Никакого зоопарка SDK. Все LLM-провайдеры (Groq, Google Gemini, OpenRouter, DeepSeek, APINET) подключаются через единый `AsyncOpenAI` клиент с разными `base_url` и `api_key`.
   - Имена моделей, `base_url`, таймауты и температура берутся ТОЛЬКО из конфига (`roles.yaml` / `config.py`). Хардкод имен моделей в коде запрещен.
4. **Burnout Guard & Safety**:
   - В режиме `RED` (🟥) и при `mentor_enabled = False` жесткие тон-блоки физически исключаются из сборщика контекста (`ContextBuilder`). Это проверяется юнит-тестами.
5. **Single-User**:
   - Система рассчитана строго на одного владельца (`OWNER_ID`). Никакой мультитенантности, регистрации и биллинга.
