# Правила работы по шагам и тестирования

- Работаем строго по одному шагу из `docs/09-PHASE-0-1-PLAN.md` за итерацию.
- После написания кода для шага обязательно:
  1. Проверить линтером (`ruff check .`).
  2. Написать/обновить pytest-тесты для новой логики и прогнать их.
  3. Не переходить к следующему шагу без подтверждения пользователя.
- **Авто-коммит и push**: когда `pytest` и `ruff check .` прошли на 100% без ошибок и в `git status` проверено, что секреты (`.env`, `.env.*` кроме `.env.example`) не попали в индекс, ты ОБЯЗАН автоматически выполнить:
  1. `git add -A`
  2. `git commit -m "<type>(<scope>): <описание>"` — формат Conventional Commits (`feat`, `fix`, `test`, `docs`, `chore`, `refactor`)
  3. `git push`
  Если тесты или линтер не зелёные, либо в индексе обнаружен секрет — НЕ коммить, сначала исправь проблему.
