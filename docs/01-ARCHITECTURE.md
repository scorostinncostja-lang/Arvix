# 01 · Архитектура

## 1. Одно ядро, пять лиц

```
   Telegram (телефон) ⇄ long polling, без вебхука
   Приложение: Mini App · телефон (PWA) · терминал `arvix` ⇄ HTTPS / ssh-туннель → API в службе бота
                          │
   Claude Code (дом ~/Arvix) ── MCP + хуки + строка состояния ──┐
   Чат Claude Desktop ─────── MCP ─────────────────────────────┤      ┌────────────────────────┐
   Терминал: arvix … ──────── CLI ─────────────────────────────┤      │ голова: claude -p       │
                          ▼                                    ▼      │ (подписка Claude,       │
                  arvix-telegram (systemd) ───────────────► Bot ──────┤  свой системный промпт, │
                          │                                           │  JSON по схеме)         │
                          ▼                                           └────────────────────────┘
                 ядро arvix/ — L0: формулы, режимы, штрафы, нагрузка (без ИИ)
                          │
            ~/.local/share/arvix/arvix.db   журнал событий (SQLite, append-only)
            Obsidian-хранилище              профиль, цели, роадмапы, конспекты, отчёты дней
```

Код — пакет `arvix-claude/arvix/`, чистый Python 3.11+ без зависимостей. Один и тот же `Core` используют
Telegram-бот, MCP-сервер (Claude Code и Claude Desktop) и CLI: разные процессы, одна база, блокировка
`BEGIN IMMEDIATE` на запись.

| Лицо | Файлы | Что умеет | Чего не умеет |
|---|---|---|---|
| **Telegram-бот** | `telegram/bot.py`, `scheduler.py`, `templates.py`, `daemon.py`, `api.py`, `fmt.py` | Проактив (брифинг, напоминания, разбор, ретро, «пишет первым»), кнопки, свободный текст и голос через голову, действия интерфейса по словам (без команд) | Работает, пока жив процесс: ноутбук спит — бот молчит (решение: сервер, [07-OPERATIONS.md](07-OPERATIONS.md)) |
| **Приложение** | `web/server.py`, `web/api.py`, `web/hub.py`, `web/auth.py`, `web/static/`, `tui.py` | Mini App, PWA на телефоне, терминал: задачи, таймер, разговор, заметки, прогресс; живые обновления. Изменения — через одну очередь главного потока службы бота ([05-INTERFACES.md §7](05-INTERFACES.md#7-приложение-mini-app-телефон-терминал--d26)) | Без службы бота не работает; наружу — только через HTTPS (Caddy) |
| **Плагин Claude Code** | `.claude-plugin/`, `skills/`, `hooks/`, `output-styles/`, `mcp_server.py`, `hooks.py`, `statusline.py` | Стиль «Arvix», 9 скиллов, 12 MCP-инструментов, состояние в сессии, строка состояния | Проактив: Claude Code отвечает только когда с ним говорят |
| **Чат Claude Desktop** | `mcp_server.py` через `arvix desktop-mcp` | Те же 12 инструментов | Нет скиллов и хуков |
| **CLI `arvix`** | `cli.py` | Всё без ИИ: отчёты, сон, траты, статус, интервью, настройка, проверка | Не разговаривает |
| **claude.ai** | `deploy/claude-ai/` | Голос и методика без доступа к журналу | Цифр состояния нет и он их не выдумывает (`<stateless>`) |

## 2. Три слоя

```
┌──────────────────────────────────────────────────────────────────────────┐
│  L2 · СОВЕТ (фон или по просьбе, никто не ждёт)                          │
│  22:30 разбор: оценка дня + 2 вопроса · вс 20:00 ретро: паттерны →       │
│  директивы с evidence · по блокам интервью: разложить ответы в структуру │
│  Роль analyst (claude -p) и скилл retro в Claude Code                    │
└───────────────────────────────┬──────────────────────────────────────────┘
                                │ директивы и факты в журнале
┌───────────────────────────────┴──────────────────────────────────────────┐
│  L1 · ГОЛОС (один вызов на сообщение)                                    │
│  Telegram: claude -p с промптом из prompt.py → JSON {reply, actions}     │
│  Claude Code: стиль + хук состояния + MCP-инструменты                    │
│  Выход: текст человеку + actions, которые исполняет код                  │
└───────────────────────────────┬──────────────────────────────────────────┘
                                │ вызывает операции Core
┌───────────────────────────────┴──────────────────────────────────────────┐
│  L0 · РЕФЛЕКСЫ (0 вызовов модели)                                        │
│  rules.py формулы · daily.py закрытие дня, материализация, Протокол Ноль │
│  load.py автонагрузка · scheduler.py проактив · safety.py маркеры        │
│  core.py операции с проверками · state.py свёртка · store.py журнал      │
└──────────────────────────────────────────────────────────────────────────┘
```

### L0 — рефлексы
Работает всегда, даже если подписка Claude исчерпана или нет сети: напоминания, кнопки, XP/HP, закрытие дня,
режим, нагрузка. Правило: если функцию можно описать формулой или таблицей решений — она здесь. Модель про эти
числа ничего не решает, она их только читает.

### L1 — голос
Единственный слой, который разговаривает. В Telegram — один вызов `claude -p` на сообщение, без MCP, скиллов
и пользовательских настроек (`--setting-sources ""`, `--strict-mcp-config`), с собственным системным промптом
из [04-AI-LAYER.md](04-AI-LAYER.md) и JSON-схемой ответа. Модель возвращает `reply` и `actions`; код исполняет
actions через `Core` и честно дописывает к ответу, что реально записано, а что отказано (`brain.apply_actions`).
В Claude Code L1 — сама сессия Claude: стиль задаёт голос, хук подкладывает состояние, инструменты MCP — руки.

### L2 — совет
Никогда не стоит в цепочке ответа. Три точки входа:
- **вечерний разбор** — роль `analyst`: одна честная оценка дня и два вопроса под этот день (схема `DEBRIEF_SCHEMA`);
- **недельное ретро** — роль `analyst`: паттерны по сырой ленте событий за 7 дней, директивы с `evidence`
  (id событий; без доказательств код отклоняет) и инсайты (`RETRO_SCHEMA`);
- **разбор блока интервью** — роль `voice`: свободные ответы → цели, черты, факты, шаблоны (`EXTRACT_SCHEMA`).

В Claude Code то же делает скилл `retro` через инструмент `analyst`. Ролей две (`voice`, `analyst`), обе — Claude
по подписке; модель каждой — в конфиге (правило №4). Отдельных «Planner», «Researcher», «Chief» нет — ❌ D10 в
[09-DECISIONS.md](09-DECISIONS.md).

## 3. Потоки

### 3.1. Сообщение в Telegram
```
update → Bot.handle: владелец? → refresh (догнать чужие события, закрыть дни)
  → фото? команда? текст
  текст: safety-маркеры (L0) → ожидаемый ответ? (отчёт, причина, разбор, интервью, сон, правка распорядка — L0)
       → иначе голова: system_prompt(core, message, history 10) + claude -p → {reply, actions, learning}
       → валидаторы: 🟥 стоп-слова → перегенерация; learning без источника → перегенерация; clip
       → apply_actions → Core → события → ответ + «✅ что записано / ⚠️ что отказано»
```
Голова недоступна (лимит, сеть, таймаут 180 с) — шаблон `FALLBACK`, сообщение уже в журнале, учёт и напоминания
работают дальше.

### 3.2. Напоминание (без ИИ)
```
daemon: getUpdates ждёт ≤ 20 с → Scheduler.tick() каждый оборот
  T−5  «Через N мин: задача» [Начать] [Отложить 15] [Не смогу]
  T+0  «Блок пошёл. Телефон — убрать»
  T+конец «Сделано: задача?» [✅ Да] [⚠️ Частично] [❌ Нет]
  → кнопка → Core.complete/fail/defer → XP/HP → ответ шаблоном
```
Каждое сообщение дедуплицируется ключом `message_out.key`: после сна ноутбука ничего не дублируется, пропущенное
отправляется только в разумном окне (брифинг 3 ч, проверка 3 ч, T+0 — 10 мин).

### 3.3. Просьба изменить план
```
«Арвикс, в 15:00 хочу погулять» → L1 видит в контексте выполнение, глубокую работу, долг, квоты, режим
  (в Claude Code — инструмент check_request с конфликтами по времени)
  → цена одной строкой с цифрами + один вариант (decision_rule)
  → человек выбирает → L1 фиксирует: defer_task / cancel_task(reason) / add_task
```
Решение «да/нет» принимает человек. Модель формулирует цену, опираясь только на числа из контекста. Единственный
жёсткий запрет живёт в коде: при долге ≥ 2 новые задачи сферы `social` не создаются (кроме 🟥), пока долг не закрыт или не
списан с обоснованием ([02-MECHANICS.md §4](02-MECHANICS.md#4-долг-)).

### 3.4. Вечерний разбор
```
22:30 → L0 собирает факты дня (tpl.debrief_facts) → analyst: оценка + 2 вопроса → одно сообщение
  → человек отвечает одним сообщением → голова: вывод «что меняем завтра» + actions
  → debrief_completed → ежедневная заметка Obsidian: блок «Арвикс» и пустые поля frontmatter
```
Пропущенный разбор стоит −8 HP, но только если бот его реально задавал (ключ `debrief:<дата>` в журнале).

### 3.5. Закрытие дня (L0)
`daily.catch_up` при любом `refresh` любого процесса: закрывает все незакрытые дни до вчерашнего (после `rollover`,
по умолчанию 04:00), максимум 14 назад, ровно одним событием `day_closed` на день; завершает Протокол Ноль;
раз в неделю пересматривает автонагрузку; материализует задачи сегодняшнего дня из шаблона; пересчитывает режим.
Полный порядок — [02-MECHANICS.md §11](02-MECHANICS.md#11-закрытие-дня--порядок-операций--dailyclose_day).

## 4. Где что живёт

| Что | Где | Переживает |
|---|---|---|
| Журнал событий | `~/.local/share/arvix/arvix.db` (SQLite, WAL) | удаление плагина, переустановку, смену ноутбука (бэкап) |
| Транспортное состояние | таблица `runtime` там же: offset Telegram, чего бот ждёт, черновик распорядка, кэш хука | рестарт бота |
| Конфиг и токен бота | `~/.config/arvix/config.toml`, права 600 | — |
| Токен подписки на сервере | `~/.config/arvix/claude.env`, права 600 | — |
| Копия плагина | `~/.local/share/arvix/app` — путь без пробелов и кириллицы, его видят systemd, Claude Code и Claude Desktop | перенос репозитория |
| Профиль, цели, роадмапы, отчёты, выводы | хранилище Obsidian по местам `[vault_paths]` | — это и есть второй мозг |
| Бэкапы | `~/.local/share/arvix/backups/` (14 копий, таймер) и `~/backups/` на сервере (7 копий, cron) | — |

**Удалённый режим.** Если в конфиге есть `[remote] host`, MCP-сервер, хук, строка состояния и CLI ноутбука не открывают
локальную базу, а запускают тот же скрипт на сервере по SSH (`remote.py`, stdin/stdout насквозь). Одна база, одна
история, никаких копий SQLite туда-обратно. Хранилище синхронизирует `rsync` по таймеру раз в 2 минуты в обе стороны
(новее побеждает, ничего не удаляется). Подробно — [07-OPERATIONS.md](07-OPERATIONS.md).

## 5. Отказы и что при них происходит

| Отказ | Поведение | Статус |
|---|---|---|
| Голова недоступна (лимит подписки, сеть, регион) | Бот отвечает `FALLBACK`; при ошибке региона — подсказка про VPN. Напоминания, кнопки, XP/HP, закрытие дня — без изменений | ✅ `test_brain_down_gives_template` |
| Ноутбук спал / бот был выключен | Дни закрываются задним числом, но без штрафов за вопросы, которых бот не задавал: `asked = day.msgs_out > 0` | ✅ `test_unasked_tasks_fail_without_damage_or_debt` |
| Сеть пропала на минуту | Long polling с экспоненциальной паузой до 20 с; упавший апдейт не зацикливает бота (offset пишется до обработки) | 🧪 `daemon.py` |
| Два процесса пишут одновременно | `BEGIN IMMEDIATE` + `busy_timeout 15 с`; `catch_up` идемпотентен | ✅ `test_catch_up_is_idempotent` |
| Сервер недоступен в удалённом режиме | Хук сообщает «сервер недоступен», строка состояния показывает последнее с пометкой ⚠, `arvix doctor` объясняет | 🧪 |
| Модель вернула не JSON или ошибку | `Brain.ask` → `None` → шаблон; `last_error` в журнале процесса | ✅ |
| Модель выдумала id задачи | `Core.resolve_task` не находит → отказ дописывается к ответу «⚠️ Не выполнено» | ✅ `test_actions_are_applied_and_reported_honestly` |
| Сообщение пришло, пока бот был без сети, и дублирует ответ | `asked_at` в ожидании: сообщение старше вопроса ответом не считается | ✅ `test_stale_duplicate_after_outage_is_not_next_answer` |

## 6. Безопасность и приватность

- **Single-user.** Все входящие проверяются на `owner_id`, остальное молча игнорируется. ✅ `test_strangers_are_ignored`.
- **Секреты.** Токен бота — только в `config.toml` (600), вводится скрытым вводом в терминале, в чаты и логи не попадает.
  Токен подписки на сервере — `claude.env` (600), скрипт `server-claude-token.sh` не выводит его на экран. В git — ничего.
- **Что уходит наружу.** В Anthropic — текст сообщений, контекст-пакет (состояние, задачи, факты памяти, директивы)
  и, если голова читает хранилище (`[brain] vault_tools = true`, инструменты Read/Grep/Glob), содержимое заметок,
  к которым она обратилась, и присланные файлы, которые она прочитала (фото, PDF, кадры видео — D29). Голос и звук
  видео — в сервис STT, если он не локальный (§8 07-OPERATIONS). В Telegram — переписка с ботом. Больше никуда.
- **Что модель не может.** Включить ментора обратно (инструмента нет, `profile_set("mentor_enabled")` отклоняется),
  писать в журнал напрямую, удалять заметки, перезаписывать чужую заметку без явного `force`, выполнять код,
  ходить в сеть. Все её действия — из закрытого списка `ACTION_TYPES` (18 типов) или 12 MCP-инструментов,
  каждое проходит проверки `Core`. ✅ `test_no_tool_can_reenable_mentor`, `test_notes_write_into_vault_structure_safely`.
- **Внедрённые инструкции.** Голова читает заметки хранилища — в них может оказаться текст, адресованный модели.
  Ущерб ограничен тем же списком actions: худшее — лишняя задача, факт в памяти или ложный `safety_flag`
  (выключает ментора до ручного `/mentor on`, это видно в `/status`). Ни удалений, ни сети, ни секретов.
- **Известное ограничение.** Маскирования персональных данных перед отправкой в модель нет, защищённых папок
  хранилища нет: голова видит всё, что в `vault`. 📋 R5 в [08-ROADMAP.md](08-ROADMAP.md).
- **Бэкап.** Снимок базы через `sqlite3 .backup` (целостный при работающем боте), проверка `integrity_check` перед
  сохранением. Экспорт в Obsidian — второй, человекочитаемый бэкап.

## 7. Стек

| | Выбор | Почему |
|---|---|---|
| Язык | Python 3.11+, стандартная библиотека | Нечему ломаться при обновлениях; ставится копированием папки |
| Хранилище состояния | SQLite (WAL) | Один пользователь, один файл, бэкап одной командой |
| Голова | `claude -p` по подписке Claude Pro | Нет API-ключей и счетов; `--json-schema` даёт структурированный ответ; модель — в конфиге |
| Telegram | Bot API через `urllib`, long polling | Ни домена, ни вебхука, ни сервера для старта |
| Планировщик | Тик в цикле long polling (≤ 20 с) | Нет отдельного процесса и jobstore; дедупликация ключами в журнале |
| Второй мозг | Obsidian-хранилище на диске, поиск по основам слов | Векторный поиск на сотнях заметок не окупается |
| Сервер | Любой VPS с systemd; rsync для хранилища | Чтобы бот писал, когда ноутбук закрыт |
| Тесты | `unittest`, 137 тестов, без сети и без ИИ | `python3 -m unittest discover -s tests -t .` из `arvix-claude/` |

Чего в стеке нет и не будет: Docker, Postgres, Redis, очереди, TWA, WebSocket, векторная БД, несколько LLM-провайдеров.
Прототип на этом стеке лежит в `archive/v1-docker/` — [09-DECISIONS.md D1](09-DECISIONS.md).
