# 04 · ИИ-слой

## 1. Почему не «просто системный промпт»

Один большой статичный промпт даёт три проблемы: он не знает состояния, он длинный, и модель нарушает его под
давлением диалога. Поэтому промпт **собирается кодом** из слоёв, а всё, что можно посчитать, считает L0 —
модель получает готовые числа и не может их «уговорить».

```
┌─ 1. КОНСТИТУЦИЯ ─── arvix/constitution/*.md · статична, кэшируется · 8 секций
├─ 2. ПРИМЕРЫ ГОЛОСА ─ fewshot.json · 8 пар «ситуация → ответ», жёсткие помечены harsh
├─ 3. КАНАЛ ───────── channel_telegram.md · формат и контракт ответа (только Telegram)
├─ 4. ОБРАЩЕНИЕ ───── имя и грамматический род из профиля
├─ 5. ТОН-БЛОК ────── выбирает Burnout Guard, 1 из 4 · модель его не выбирает
├─ 6. КОНТЕКСТ ────── build_context(): состояние, задачи, неделя, цели, память — собирает код
├─ 7. ИСТОРИЯ ─────── 10 последних сообщений (message_in / message_out)
└─ 8. ДОПОЛНЕНИЯ ──── режим /answer, протокол возвращения, валидатор при перегенерации
```

Порядок — сначала статичное, потом динамичное: префикс промпта кэшируется, переменная часть стоит в конце.
Сборка — `arvix/prompt.py`. Размер в Telegram ≈ 9 тыс. символов в 🟩, ≈ 6.6 тыс. в 🟥 (без жёстких примеров и
правила решений).

## 2. Конституция (слой 1)

Модульная, в XML-тегах: секции подменяются программно, не переписывая текст целиком. Источник правды —
`arvix-claude/arvix/constitution/`; из тех же файлов генерируются стиль Claude Code и инструкции claude.ai
(`scripts/build_assets.py`, тест следит, что сгенерированное не устарело).

| Секция | Суть | В мягком режиме |
|---|---|---|
| `identity` | Арвикс — ментор одного человека, не ассистент. Успех — как редко он нужен. Не рассуждает о своей природе, но на прямой вопрос честно: ИИ-система, настроенная как ментор | да |
| `mission` | Отвечает за систему (план, напоминание, данные, разбор); человек — за исполнение | да |
| `voice` | Короткие предложения, суть первой строкой, без лести, цифры не смягчаются, критика действия, не личности, максимум один вопрос | да |
| `autonomy_rule` | Сократовский режим: на учебный вопрос — направление, 2–3 источника, время, подсказка. Готовый ответ — только по `/answer`. Первоисточник обязателен, ссылка — только настоящая | да |
| `decision_rule` | Просьба изменить план — сделка: цена в цифрах + один вариант, решение за человеком, выбор записывается инструментами | **нет** |
| `honesty` | Нет данных — сказать и спросить одно; несостыковки — спокойно; не выдумывать источники | да |
| `boundaries` | Без медицинских, юридических, инвестиционных советов; не решает домашку; не изображает близость; не развлекает | да |
| `safety_override` | Отменяет всё: при настоящей беде — человеческий тон, живой человек рядом, 112; не диагностирует; ставит `safety_flag` | да |

Плейсхолдеры: `{support}` — контакт поддержки из интервью, `{emergency}` — 112 (`prompt.EMERGENCY`).

## 3. Голос: примеры и тон-блоки (слои 2 и 5)

Характер воспроизводится примерами надёжнее, чем инструкцией «будь жёстким». Восемь примеров:

| # | Ситуация | Чему учит | harsh |
|---|---|---|---|
| 1 | Просит отдых при низком выполнении | Цена в цифрах и два варианта, «выбирай, запишу» | да |
| 2 | То же при высоком выполнении | «Иди» с временем возврата | нет |
| 3 | Учебный вопрос | Сократовский режим: вопрос себе, первоисточник со ссылкой, 20 минут | нет |
| 4 | Провал с оправданием | Факт отдельно от оправдания, без морали | да |
| 5 | Отчёт об успехе | Признание фактом, без похвалы | нет |
| 6 | Попытка поболтать | Одна строка и возврат к делу | нет |
| 7 | 🟥 | Человеческий тон, ноль метрик | нет |
| 8 | Несостыковка в отчёте | Спокойно назвать цифры | да |

Если Арвикс звучит не так — правится `fewshot.json`, а не правила.

Тон-блоки — по режиму Burnout Guard ([02-MECHANICS.md §6](02-MECHANICS.md#6-burnout-guard--выключатель-жёсткости-)):
`tone_norm` (требовательный, спокойный), `tone_pressure` (жёстко и коротко, без унижения), `tone_yellow` (твёрдо,
без давления, один вопрос о причине), `tone_red` (человеческий, тёплый, без метрик и задач).

### 3.1. Мягкий режим — правило №5 в коде ✅
`prompt.is_gentle(mode, mentor_enabled)`: 🟥 **или** выключенный ментор. Тогда физически не попадают в промпт:
три жёстких тон-блока, примеры с `harsh: true`, секция `decision_rule`; контекст сокращается до времени, сна и
«одной маленькой вещи» (самой короткой открытой задачи). Тесты `tests/test_prompt_safety.py` проверяют это для
Telegram-промпта, для хука Claude Code и для статичного стиля.

## 4. Контекст-пакет (слой 6)

Собирается кодом (`context.build_context`) из состояния, за миллисекунды. Формат — компактный текст, не JSON.
Пустые строки не выводятся. Числа полные, без округления в пользу человека. Реальный пример (школьник, четверг 16:32,
распорядок с обязательной школой):

```
СЕЙЧАС: чт 12.11.2026, 16:32 (Europe/Moscow). Режим: 🟩 НОРМА. Тип дня: Учебный.
ЧЕЛОВЕК: Дастан · сон по плану 23:00–07:30 (норма 8ч30м)
СОСТОЯНИЕ: ур.1 (0/100 XP) · HP 100 · стрик 0 дн · сезон S1 нед.1 Бронза (SP 0.0)
СЕГОДНЯ: 0/3 задач (0%) · глубокая 0м из 1ч05м · сон 6ч40м
ЗАДАЧИ:
  [4b08bda9] 16:00 ⏳ Математика ОГЭ: задания 20–25 · 65м imp4 diff4 deep отчёт:report
  [fb369782] 18:30 ⏳ Физика: §12 Перышкин + 5 задач · 30м imp3 diff3 отчёт:report
  [e23ebe06] 20:00 ⏳ Зал · 30м imp2 diff3 отчёт:photo
ЗАНЯТО: 08:30–14:30 Школа
НЕДЕЛЯ: сделано 0м/10ч25м · глубокая 0м/5ч25м · квоты: спорт 0/3 · социум 0/2 · новое 0/1 · отдых без экрана 0/3
НАГРУЗКА: бюджет 10ч25м/нед (глубокая 5ч25м) · запланировано 2ч05м · пересмотр 19.11 · авто: глубокая работа 5ч25м, учёба 2ч30м, спорт 2ч30м, обязательное 30ч00м
ГЛАВНАЯ ЦЕЛЬ: [9a48ab0b] ОГЭ 2027: математика 5, физика 5, английский 5 к маю (зачем: Поступить в профильный класс)
ПАМЯТЬ: после 21:00 залипает в шортсы и CS2
ЗНАКОМСТВО: отвечено 5/52 — следующий блок «Ядро»
```

Полный набор строк: СЕЙЧАС · ЧЕЛОВЕК · СОСТОЯНИЕ · СЕГОДНЯ · ЗАДАЧИ (с id — модель ссылается на задачи только по ним) ·
ЗАНЯТО · ДОЛГ · ЗАВТРА · НЕДЕЛЯ · НАГРУЗКА (+ ⚠️ перегруз) · РАСПОРЯДОК (если шаблонов нет) · АВТОНОМНОСТЬ ·
ДИРЕКТИВЫ (до 5, по приоритету) · ГЛАВНАЯ ЦЕЛЬ · ЭТАПЫ · ЧЕРТЫ (4 самые сильные) · ПАМЯТЬ (до 8 фактов) ·
ПОСЛЕДНЕЕ (вчера, позавчера, разбор) · ЗНАКОМСТВО (прогресс интервью).

**Память в контексте:** 3 факта тем `goal`, `fear`, `weakness`, `trigger` всегда + остальные по совпадению основ слов
с сообщением человека (×10) и уверенности. Факты с истёкшим `valid_until` не попадают. Векторного поиска нет —
❌ [09-DECISIONS.md](09-DECISIONS.md) D2.

## 5. Голова Telegram — `claude -p` (`arvix/brain.py`)

Один вызов на сообщение, по подписке Claude, без API-ключа:

```
claude -p <сообщение> --system-prompt <слои 1–8> --output-format json --json-schema <схема>
       --setting-sources "" --strict-mcp-config --disable-slash-commands --no-session-persistence
       --permission-mode dontAsk [--model <из [roles.*]>]
       [--tools Read,Grep,Glob --add-dir <хранилище>]   # если [brain] vault_tools = true
```

- Без пользовательских настроек, MCP и скиллов: ~1.5 тыс. служебных токенов вместо ~43 тыс.
- `ARVIX_BRAIN=1` в окружении — хуки плагина в этом вызове молчат.
- Таймаут — `[brain] timeout_sec` (180 с). Ошибка, не-JSON, лимит подписки → `None` → ответ шаблоном L0.
- Модели ролей — только в конфиге: `[roles.voice]` (чат, интервью, распорядок) и `[roles.analyst]` (разбор, ретро).
  По умолчанию обе `sonnet`. Экономнее — `haiku` для `voice`; глубже разбор — `opus` для `analyst` (быстрее расходует лимит Pro).

### 5.1. Схемы ответа

| Схема | Кто зовёт | Поля |
|---|---|---|
| `VOICE_SCHEMA` | свободный текст, ответ на разбор | `reply`, `actions[]`, `learning` |
| `DEBRIEF_SCHEMA` | вечерний разбор | `assessment` (1–2 предложения), `questions` (ровно 2) |
| `RETRO_SCHEMA` | ретро недели | `message` (≤ 900 символов), `directives[]` с `evidence`, `insights[]` |
| `EXTRACT_SCHEMA` | конец блока интервью | `summary`, `actions[]` (цели, черты, факты, поля профиля, шаблоны) |
| `TEMPLATES_SCHEMA` | `/schedule`, после блока «Распорядок дня» | `summary`, `templates[]` (дни недели, тип, блоки) |

### 5.2. Actions — руки модели
Модель ничего не меняет сама. Она возвращает список действий, код исполняет каждое через `Core` с проверками и
дописывает к ответу, что **реально** записано («✅ Английский +11 XP») и что отказано («⚠️ Не выполнено: …»).
18 типов (`brain.ACTION_TYPES`): `add_task`, `complete_task`, `fail_task`, `defer_task`, `cancel_task`, `start_task`,
`log_sleep`, `log_expense`, `log_social`, `remember`, `note`, `profile_set`, `set_goal`, `add_trait`,
`declare_reason`, `learning_question`, `safety_flag`, `set_template`.

Чего в списке нет намеренно: включить ментора, списать долг, начислить XP или HP, удалить что-либо, записать
директиву (это только L2 с доказательствами). Страховки от типичных промахов модели: забыла `report` — отчётом
становятся слова человека; написала «до 20:30» в `deadline` вместо `start` — старт вычисляется кодом.

## 6. Валидаторы ответа (L0, без модели)

| # | Проверка | Действие | Статус |
|---|---|---|---|
| 1 | Режим 🟥, а в ответе слова жёсткости (`дисциплин`, `провал`, `штраф`, `лень`, `xp`, `hp`, `долг`…) | одна перегенерация с пометкой; снова — шаблон `GENTLE_FALLBACK`, actions отбрасываются | ✅ `test_gentle_validator_replaces_harsh_reply` |
| 2 | Ответ помечен как учебный (`learning`), а первоисточник не назван (ни ссылки, ни учебника, параграфа, документации) | одна перегенерация; снова — приписка «сверь с учебником или документацией» | ✅ `test_learning_answer_needs_a_named_source_not_a_url` |
| 3 | Проактивный текст модели длиннее лимита | `clip` по границе предложения: оценка дня 300, ретро 900, сводка 500 | ✅ |
| 4 | Модель сослалась на несуществующую задачу | отказ `Core.resolve_task` в «⚠️ Не выполнено» | ✅ |
| 5 | Числа в тексте, которых нет в контексте | — | ❌ D9: код и так дописывает реальные результаты; правка чисел регуляркой ломает фразы |
| 6 | Готовый ответ на учебный вопрос без `/answer` | — | 📋 сейчас держится промптом и примером #3 |

**Валидатор источника не требует URL** — сознательно. Требование ссылки учит модель выдумывать адреса; учебник
с параграфом («Перышкин, 9 класс, §12») для подготовки к экзамену — настоящий первоисточник.

## 7. Совет (L2)

Совет никогда не стоит в цепочке ответа (правило №2). Промпт аналитика — короче голоса:
`identity` + `mission` + `honesty` + правила аналитика:

```
Ты не пересказываешь события — их видно и так. Ты ищешь связь, которую человек сам не замечает.
Каждый вывод опирается минимум на 3 события — указывай их id в evidence.
Вывод без доказательств отбрасывается кодом. Лучше один вывод, чем пять догадок.
Если значимого паттерна нет — так и скажи. Периоды с safety_flag не разбираются на эффективность.
```

| Когда | Вход | Выход |
|---|---|---|
| Вечерний разбор, 22:30 | факты дня (код), сырая лента событий дня с id, контекст | оценка дня + 2 вопроса в одно сообщение; ответ человека → голос: вывод «что меняем завтра» |
| Ретро, вс 20:00 (повтор через час при сбое) | лента событий за 7 дней, контекст | сообщение человеку + 1–5 директив + инсайты |
| Конец блока интервью | вопросы и ответы блока | цели, черты, факты, поля профиля, шаблоны → actions |
| Claude Code, скилл `retro` | инструмент `analyst` (`events`, `directive`, `insight`) | то же, в диалоге |

**Директива** — вывод, который голос читает как факт: `kind` (focus · warning · schedule_change · insight ·
quota_push), `text`, `voice_hint` (когда напомнить), `priority` 1–5, `valid_until` (по умолчанию 7 дней),
`evidence` — id событий. Код отклоняет директиву без доказательств или со ссылкой на несуществующее событие
(инвариант 5, [03-DATA-MODEL.md §4](03-DATA-MODEL.md#4-инварианты-которые-проверяются-тестами)).

## 8. Долговременная память

Три вида, не смешиваются:

| Вид | Где | Что | Кто пишет |
|---|---|---|---|
| События | журнал `events` | что произошло; не удаляется | код |
| Факты и черты | `fact_remembered`, `trait_set`, `goal_set` | что верно о человеке: страхи, триггеры, привычки, цели, люди | голос (`remember`, `add_trait`, `set_goal`), разбор интервью, человек |
| Директивы | `directive_created` | что делать сейчас; со сроком годности | только L2 с доказательствами |

Забыть факт — `profile` action=`forget` (компенсирующее событие `fact_retracted`). Увидеть всё, что Арвикс знает, —
`/export` → `05_System/Профиль Арвикса.md` или «покажи мой профиль».

## 9. Claude Code: тот же Арвикс через плагин

В Claude Code голосом служит сама сессия Claude, поэтому слои распределены иначе:

| Слой | Где | Когда |
|---|---|---|
| Конституция без `decision_rule`, правила инструментов, мягкие примеры | стиль `output-styles/arvix.md` (генерируется) | всегда, в доме `~/Arvix` |
| Обращение, тон-блок, `decision_rule` и жёсткие примеры (вне мягкого режима), контекст, блок первой встречи | хук `SessionStart` → `prompt.hook_context` | старт, resume, clear, compact |
| Строка «сейчас · режим · HP · день» и новый тон-блок при смене режима | хук `UserPromptSubmit` | каждое сообщение |
| Руки | 12 MCP-инструментов (`context`, `day`, `task`, `log`, `profile`, `interview`, `check_request`, `debrief`, `analyst`, `notes`, `mode`, `export`) | по требованию модели |
| Порядок действий | 9 скиллов | по описанию или `/arvix:<имя>` |

Хуки срабатывают только в доме Арвикса (маркер `.arvix-home`) — обычные кодинг-сессии не платят токенами.
Стоимость плагина в сессии — около 1.1 тыс. токенов. Первая встреча: пока интервью не начато и шаблонов нет,
хук добавляет блок `<first_session>` — Арвикс сам представляется и начинает знакомство.

## 10. Экономика

Всё работает на подписке Claude Pro — общий лимит с обычной работой в Claude Code:
- сообщение в Telegram — один вызов ≈ 2–5 тыс. токенов на вход;
- разбор — один-два вызова в день, ретро — один в неделю, разбор блока интервью — один на блок;
- напоминания, кнопки, команды, закрытие дня, брифинг — **ноль** вызовов.

Лимит кончился — бот отвечает шаблоном, а учёт, напоминания, XP/HP и режим работают дальше.
