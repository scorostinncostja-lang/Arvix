# 07 · Второй мозг и обучение

## 1. Синхронизация Obsidian — через Git

### Почему не свой протокол
Двусторонняя синхронизация ПК ↔ iOS ↔ сервер со своим протоколом — это две недели работы и вечные конфликты. Git решает это бесплатно и надёжно.

```
        ПК (Linux, Obsidian + плагин Obsidian Git)
                    ↕ автокоммит каждые 10 мин
        ┌───────────────────────────────┐
        │  Приватный Git-репозиторий     │  ← единственный источник правды
        └───────────────────────────────┘
          ↕ pull/push                 ↕ pull каждые 10 мин + вебхук
   iPhone (Working Copy               arvix-worker
   + Obsidian)                        (клон на сервере)
```

**Правила:**
- Арвикс пишет **только** в папку `Arvix/` внутри репозитория. Твои заметки он не редактирует никогда — только читает
- Коммиты Арвикса подписаны `arvix-bot`, чтобы в истории было видно, кто что писал
- Конфликты решает git. При конфликте в папке Арвикса — его версия отбрасывается, он перезапишет на следующем цикле
- Вебхук от Git-хостинга → мгновенная переиндексация изменённых файлов
- Медиафайлы (изображения в заметках) — через Git LFS или исключаются из синка сервера

## 2. Индекс и поиск

### Почему не «отдать все заметки модели»
Сотни файлов = сотни тысяч токенов на каждый вопрос. Медленно, дорого, и модель теряется. Правильно — найти 5-8 нужных кусков и отдать только их.

### Пайплайн индексации

```
git pull → diff → изменённые .md файлы
  → парсинг: разбивка по заголовкам (## / ###), сохранение heading_path
  → чанки 300-600 токенов с перекрытием 50
  → content_hash → пропуск неизменившихся
  → эмбеддинг (локальная модель или дешёвый API)
  → UPSERT в note_chunks (pgvector)
```

Локальная модель эмбеддингов (`intfloat/multilingual-e5-base` или аналог, 768 dim) — работает на CPU VPS, не стоит денег, поддерживает русский. Индексация всей базы — минуты, инкремент — секунды.

### Гибридный поиск

```sql
-- Полнотекстовый (BM25-подобный через ts_rank)
SELECT id, ts_rank(tsv, query) AS score FROM note_chunks, 
       plainto_tsquery('russian', :q) query WHERE tsv @@ query

-- Векторный
SELECT id, 1 - (embedding <=> :vec) AS score FROM note_chunks 
       ORDER BY embedding <=> :vec LIMIT 30
```

Слияние через **Reciprocal Rank Fusion**: `score = Σ 1/(60 + rank_i)`. Топ-8 чанков в контекст. Время выполнения — ~150-250 мс.

### Сценарий использования

```
ЮЗЕР: Арвикс, найди у меня в заметках про технологию Bluetooth

АРВИКС: Три файла.

📄 Электроника/Беспроводные протоколы.md — раздел «Bluetooth LE»,
   писал 12.04. Профили GATT, разница Classic и LE, потребление.
📄 Проекты/ESP32-заметки.md — раздел «BLE на ESP32», код инициализации
   характеристики, 03.08.
📄 Учёба/Сети/Конспект лекции 7.md — короткий кусок, стек протоколов,
   Bluetooth упомянут вскользь.

Основное — в первом. Открыть или сделать выжимку?
```

На «сделай выжимку» → полный текст релевантных файлов в модель → структурированная сводка **со ссылками на конкретные файлы и заголовки**.

## 3. Арвикс как учитель

Это самая ценная часть проекта после дисциплины, и самая недоописанная в исходном ТЗ.

### 3.1. Проблема
«Не понимаю как, где и откуда учиться» — это не недостаток информации, а недостаток структуры. Информации избыток, поэтому паралич.

### 3.2. Роадмап — структура

```yaml
Roadmap:
  title: "Frontend Junior к июню 2027"
  goal_id: <uuid>
  nodes:
    - id: n1
      title: "JavaScript: асинхронность"
      why: "Без этого не понять ни один фреймворк и не пройти собес"
      est_hours: 14
      deps: []
      sources:
        - { kind: docs,  title: "MDN: Concurrency model", url: "...", hours: 2, primary: true }
        - { kind: video, title: "Jake Archibald: In The Loop", url: "...", hours: 1 }
        - { kind: book,  title: "You Don't Know JS: Async", chapters: "1-3", hours: 6 }
        - { kind: practice, title: "20 задач на промисы", url: "...", hours: 5 }
      checkpoint:
        kind: explain | build | test
        task: "Объясни Арвиксу event loop своими словами + напиши свой Promise.all"
      status: todo | in_progress | done
```

### 3.3. Требования к роадмапу (жёсткие)

1. **Актуальность.** Researcher обязан проверить, что источники живы и не устарели. Роадмап с мёртвыми ссылками — брак
2. **Первоисточник обязателен.** В каждом узле минимум одна ссылка на официальную документацию/спецификацию, а не только на видео и статьи
3. **Оценка часов** на каждый узел, чтобы роадмап можно было положить в бюджет недели
4. **Зависимости** явно — что без чего не имеет смысла
5. **Чекпоинт** на каждом узле: не «прочитал», а **проверяемое действие**:
   - `explain` — объяснить Арвиксу своими словами, он задаёт 3 вопроса и оценивает
   - `build` — сделать маленькую вещь
   - `test` — решить N задач
6. **Ревизия раз в месяц** — источники и порядок пересматриваются

### 3.4. Связь роадмапа с расписанием
Узлы роадмапа автоматически превращаются в задачи типа `deep_work` и попадают в план по мере продвижения. Прогресс роадмапа виден в TWA как процент и как граф.

### 3.5. Проверка понимания (`explain`-чекпоинт)

```
АРВИКС: Узел «JS: асинхронность» помечен как пройденный. Проверка.
Объясни мне event loop так, как объяснил бы человеку,
который знает программирование, но не знает JS. Три-четыре предложения.

[ответ пользователя]

АРВИКС: Стек и очередь назвал верно. Микротаски пропустил —
а это ровно то, из-за чего люди не понимают, почему Promise выполняется
раньше setTimeout(0).
Дочитай MDN, раздел про microtask queue, 10 минут. Потом одно предложение мне.
Узел пока не закрываю.
```

Это единственный способ отличить «прочитал» от «понял». И это ровно то, что делает Арвикса учителем, а не поисковиком.

### 3.6. Сократовский режим — правила

| Ситуация | Поведение |
|---|---|
| Вопрос по теме, которая есть в его роадмапе | Подсказка + отсылка к конкретному узлу и источнику |
| Вопрос по теме, которой нет в заметках | Направление + 2-3 источника + оценка времени |
| Вопрос, на который есть ответ в его заметках | «Ты это конспектировал 4 месяца назад: <файл>. Перечитай» |
| Повторный вопрос по той же теме | Указание на повтор + предложение закрепить практикой |
| `/answer` | Полный ответ, но с пометкой в логе и с источниками |
| Вопрос во время рабочего блока | «Не сейчас. Запишу в очередь, разберём в перерыве» |

Вопросы, отложенные на перерыв, копятся в очереди и разбираются одним блоком — это заодно лечит привычку отвлекаться на любой возникший вопрос.
