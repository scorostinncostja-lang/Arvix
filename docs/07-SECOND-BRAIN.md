# 07 · Обучение и второй мозг

## 1. Что реально работает в обучении

«Не понимаю, как, где и откуда учиться» — не недостаток информации, а недостаток структуры. Информации избыток, поэтому паралич. А то, что выучено, забывается за недели, если его не повторять.

Арвикс строит обучение на том, что имеет устойчивую доказательную базу в когнитивной психологии, а не на ощущении «прочитал — значит знаю»:

| Принцип | Суть | Как реализовано |
|---|---|---|
| **Активное воспроизведение** (testing effect) | Вспомнить без подсказки закрепляет сильнее, чем перечитать (Roediger & Karpicke, 2006) | Чекпоинты, карточки, «объясни своими словами» |
| **Интервальное повторение** | Повтор с растущими интервалами в момент почти-забывания | FSRS, расписание считает L0 |
| **Обратная связь** | Ошибка, найденная сразу, исправляется; найденная через месяц — закрепляется | Проверка чекпоинтов, исправления в языковых сессиях |
| **Первоисточник** | Документация и спецификация точнее пересказов | Обязательный первоисточник в каждом узле роадмапа |
| **Практика на пределе** | Задачи чуть сложнее текущего уровня | Чекпоинты `build`/`test`, уровни языковых сессий |

Анти-паттерны, которые Арвикс не поощряет: пассивный просмотр видео как «учёба», перечитывание конспектов, коллекционирование курсов, бесконечное «изучение теории» без применения.

## 2. Роадмап

### 2.1. Как появляется
1. Ты называешь цель обучения (из цели года или командой `/learn <тема>` → «составить роадмап?»)
2. Бот уточняет 2–3 вещи: текущий уровень, часы в неделю, срок, формат (книги/видео/практика)
3. Задание L2 `roadmap_research` (роль `researcher` + веб-поиск) собирает черновик в фоне. Ничего не ждёшь — придёт сообщение
4. Черновик в TWA: правишь, удаляешь узлы, подтверждаешь → `roadmap_created`
5. Следующие узлы становятся кандидатами в результаты недели при воскресном планировании

### 2.2. Структура

```yaml
Roadmap:
  title: "Frontend Junior к июню 2027"
  goal_id: <uuid>
  kind: skill            # skill | language
  nodes:
    - id: n1
      title: "JavaScript: асинхронность"
      why: "Без этого не понять ни один фреймворк и не пройти собеседование"
      est_hours: 14
      deps: []
      sources:
        - { kind: docs,     title: "MDN: The event loop", url: "...", hours: 2, primary: true, checked_at: 2026-11-01 }
        - { kind: video,    title: "...",                 url: "...", hours: 1, checked_at: 2026-11-01 }
        - { kind: book,     title: "You Don't Know JS Yet: Async & Performance", chapters: "1-3", hours: 6 }
        - { kind: practice, title: "20 задач на промисы",  url: "...", hours: 5, checked_at: 2026-11-01 }
      checkpoint:
        kind: explain | build | test
        task: "Объясни event loop своими словами + напиши свой Promise.all"
        pass_criteria: "Названы стек, очередь задач, очередь микрозадач; Promise.all проходит 5 тестов"
      status: todo | in_progress | checkpoint | done
```

### 2.3. Требования (жёсткие, проверяются валидатором черновика)
1. **Актуальность.** Каждый URL проверен HTTP-запросом (L0) при создании и раз в месяц. Мёртвая ссылка — брак. У каждого источника `checked_at`
2. **Первоисточник обязателен.** В каждом узле минимум один `primary: true` — официальная документация, спецификация или учебник, а не только видео и статьи
3. **Ссылки — только из результатов поиска.** Researcher не может вписать URL, которого не было в выдаче (тот же валидатор ссылок, 04-AI-LAYER §10)
4. **Оценка часов** на каждый узел — чтобы роадмап ложился в бюджет недели
5. **Зависимости явно** — что без чего не имеет смысла
6. **Чекпоинт** на каждом узле с критерием прохождения — не «прочитал», а проверяемое действие
7. **Узел ≤ 20 часов.** Больше — разбивается
8. **Ревизия раз в месяц** — источники и порядок (`source_freshness`, 04-AI-LAYER §8)

### 2.4. Связь с расписанием
Узел роадмапа → результат недели («Узел: асинхронность JS, чекпоинт пройден») → задачи по 60–120 минут с DoD («Прочитать MDN Event loop + 5 тезисов своими словами»). Прогресс виден в TWA процентом и графом. Узел закрывается **только** прохождением чекпоинта.

## 3. Учебный блок и проверка понимания

### 3.1. Структура учебного блока (90 минут, дефолт)
Шаблон, который бот предлагает для задач `sphere=learning` с `deep_work`:

| Минуты | Фаза | Что делаешь |
|---|---|---|
| 0–5 | Цель | Читаешь DoD задачи, формулируешь вопрос, на который ищешь ответ |
| 5–60 | Первоисточник | Читаешь/смотришь/делаешь. Телефон — в другой комнате |
| 60–80 | Воспроизведение | Закрываешь источник. Пишешь своими словами в Obsidian, что понял |
| 80–90 | Закрепление | 3–5 карточек из того, что далось трудно → `propose_srs_cards` |

Отчёт по задаче (`report`) — одна фраза о том, что из DoD сделано.

### 3.2. Чекпоинты

| Тип | Как проходит | Кто проверяет |
|---|---|---|
| `explain` | Объясняешь концепцию своими словами (текст или голос). Арвикс задаёт до 3 уточняющих вопросов по `pass_criteria` | L1, по критерию из роадмапа |
| `build` | Делаешь маленькую вещь, присылаешь ссылку/код/описание. Арвикс сверяет с критерием | L1 + владелец (самопроверка по чек-листу) |
| `test` | Решаешь N задач. Результат — число решённых | L0 (подсчёт) |

```
АРВИКС: Узел «JS: асинхронность» — время чекпоинта.
Объясни event loop так, как объяснил бы человеку, который знает программирование, но не знает JS.
Три-четыре предложения.

[ответ]

АРВИКС: Стек и очередь назвал верно. Микрозадачи пропустил — а это ровно то, из-за чего
Promise выполняется раньше setTimeout(0).
Раздел MDN про microtask queue, 10 минут. Потом одно предложение мне. Узел пока не закрываю.
В карточки: «Чем очередь микрозадач отличается от очереди задач?» [Добавить]
```

Результат — `checkpoint_attempted(passed, gaps[])`. Пробелы (`gaps`) превращаются в кандидаты карточек и в задачу «дочитать» на завтра. Это единственный способ отличить «прочитал» от «понял» — и то, что делает Арвикса учителем, а не поисковиком.

## 4. Интервальные повторения (SRS)

### 4.1. Как устроено
- Алгоритм **FSRS** (библиотека `fsrs`, open-spaced-repetition) — расписание считает L0, модель не участвует
- Карточки — таблица `srs_cards`, повторение — событие `srs_reviewed(rating)`
- Колоды: по роадмапам и языкам (`js`, `networks`, `en-vocab`, ...)

### 4.2. Откуда берутся карточки
| Источник | Как |
|---|---|
| Пробелы чекпоинтов | Автоматически кандидаты (`gaps`) |
| Учебный блок | Фаза «Закрепление» — 3–5 штук |
| Языковые сессии | Новая лексика и частые ошибки |
| Заметки Obsidian | По кнопке «карточки из этого файла» в TWA |
| Вручную | `/cards add вопрос :: ответ` или TWA |

**Карточки создаются только с твоего подтверждения.** Модель предлагает (`propose_srs_cards`), ты принимаешь или правишь. Иначе колода зарастает мусором, и повторения превращаются в повинность.

**Правила хорошей карточки** (валидатор + промпт): один факт на карточку; вопрос, на который отвечаешь своими словами, а не «да/нет»; без списков из 7 пунктов; контекст в вопросе («В JS: …»).

### 4.3. Сессия повторения
- `/cards` или напоминание в удобный слот (дефолт — 10 минут после ужина)
- В чате: вопрос → [Показать ответ] → [Забыл] [Трудно] [Хорошо] [Легко] (оценки FSRS 1–4)
- Лимиты (конфиг): до 20 новых карточек в день, до 150 повторений; если просрочено > 200 — бот предлагает режим «разгрести»: только повторения, без новых, пока очередь не станет нормальной
- Сессия = опережающий показатель для учебных и языковых целей (`source: auto`)
- Экспорт колод в формат Anki — по кнопке (анти-зависимость: карточки твои)

## 5. Сократовский режим — правила

Действует в режиме **Учитель** (04-AI-LAYER §3). Для нелучебных дел работает Помощник — прямо.

| Ситуация | Поведение |
|---|---|
| Вопрос по теме из твоего роадмапа | Подсказка + отсылка к конкретному узлу и его первоисточнику |
| Вопрос, на который ответ есть в твоих заметках | «Ты это конспектировал: <файл>. Перечитай раздел <заголовок>» |
| Вопрос по новой учебной теме | Направление + 2–3 источника из поиска + оценка времени. Предложение: «Сделать из этого узел роадмапа?» |
| Повторный вопрос по той же теме | Указание на повтор + карточка + предложение практики |
| `/answer` | Полный ответ с источниками. `learning_question(mode=direct)` — без упрёков, это метрика для тебя |
| Вопрос во время рабочего блока не по задаче блока | «Записал в inbox, разберём вечером» |
| Просьба сделать за тебя задание, которому ты учишься | Отказ + помощь с подходом: «Решать не буду — это то, чему ты учишься. С какого шага застрял?» |

## 6. Изучение языков

### 6.1. Профиль языка
```yaml
profile.languages:
  - lang: en
    level: B1            # CEFR, самооценка + проверка (§6.5)
    target_level: B2
    deadline: 2027-09-01
    purpose: "Читать документацию и пройти собеседование на английском"
```
Каждый язык — цель года (`goals`, sphere=language) с роадмапом `kind: language` и опережающими показателями.

### 6.2. Ежедневный минимум (дефолт для уровня A2–B2)
| Компонент | Минимум | Показатель |
|---|---|---|
| Повторение лексики (SRS) | 10–15 мин, все просроченные | карточки/день |
| Ввод (подкаст, видео, чтение по теме цели) | 20 мин | минуты ввода/нед |
| Вывод: разговор или письмо с ботом | 3 сессии по 15 мин в неделю | сессии/нед |
| Грамматика | по узлам языкового роадмапа | узлы/мес |

Цель модуля — **понятный ввод + регулярный вывод с исправлениями + повторение лексики**. Не «пройти курс», а пользоваться языком.

### 6.3. Сессии с Тренером (`/lang <язык> <минуты>`)
| Тип | Как |
|---|---|
| **Разговор** | Бот говорит на целевом языке на твоём уровне (чуть выше), тема — из твоей жизни или цели. Исправления — в конце каждого сообщения компактным списком: «ошибка → правильно (почему)». Можно голосом: STT распознаёт речь |
| **Письмо** | Тема на 100–200 слов → разбор: ошибки по категориям, переписанная версия, 3 выражения в карточки |
| **Ввод** | Ты присылаешь текст/ссылку на то, что читал или слушал → бот задаёт 3 вопроса на понимание, выписывает 5 выражений в кандидаты карточек |

Сессия ограничена по времени (таймер L0). Итог — `language_session(kind, minutes, errors_n)`, частые ошибки копятся по категориям (время глагола, артикли, предлоги...) и становятся узлами грамматики в роадмапе.

### 6.4. Чего бот не умеет — честно
- Оценивать произношение: STT распознаёт слова, но не даёт надёжной оценки фонетики. Для произношения — внешние ресурсы и живые люди
- Заменить живое общение: раз в месяц бот предлагает реальную практику (языковой клуб, обмен, звонок) как результат недели

### 6.5. Проверка уровня (раз в месяц)
Самооценка по дескрипторам CEFR («могу / с трудом / не могу») + письменное задание и разговорная сессия, оценённые по тем же дескрипторам. Результат — строка в месячном разборе и обновление `level`, если два месяца подряд подтверждён более высокий. Это ориентир, а не сертификат.

## 7. Синхронизация Obsidian — через Git (фаза 2)

Двусторонняя синхронизация ПК ↔ телефон ↔ сервер своим протоколом — недели работы и вечные конфликты. Git решает это бесплатно.

```
        ПК (Obsidian + плагин Obsidian Git)
                    ↕ автокоммит каждые 10 мин
        ┌───────────────────────────────┐
        │  Приватный Git-репозиторий     │  ← единственный источник правды
        └───────────────────────────────┘
          ↕ pull/push                 ↕ pull каждые 10 мин + вебхук
   Телефон (Obsidian + git-клиент)    arvix-worker (клон на сервере)
```

**Правила (фазы 2–5):**
- Арвикс пишет **только** в папку `Arvix/` внутри репозитория. Твои заметки он только читает
- Коммиты Арвикса подписаны `arvix-bot`
- Конфликт в папке Арвикса — его версия отбрасывается, он перезапишет на следующем цикле

**С фазы 6** — полный доступ к хранилищу с откатом: правка везде, кроме защищённых папок, каждое изменение отдельным коммитом, удаление только в `.trash/` с подтверждением. Правила — [13-AGENT-PLATFORM.md](13-AGENT-PLATFORM.md) §9.
- Вебхук от Git-хостинга → мгновенная переиндексация изменённых файлов
- Медиафайлы — исключаются из синка сервера (или Git LFS)
- Git не умеет выдавать права на отдельную папку, поэтому у сервера ключ с правом записи, а ограничение «только `Arvix/`» держит код: функция записи отвергает любой путь вне `Arvix/` (юнит-тест, включая `../` и симлинки)

## 8. Индекс и поиск по заметкам (фаза 2)

### Почему не «отдать все заметки модели»
Сотни файлов = сотни тысяч токенов на каждый вопрос. Медленно, дорого, модель теряется. Нужно найти 5–8 нужных кусков и отдать только их.

### Пайплайн индексации
```
git pull → diff → изменённые .md
  → разбивка по заголовкам (## / ###), сохранение heading_path
  → чанки 300–600 токенов с перекрытием 50
  → content_hash → неизменившиеся пропускаются
  → эмбеддинг (роль embed: локальная мультиязычная модель на CPU или API)
  → UPSERT в note_chunks
```

### Гибридный поиск
```sql
-- Полнотекстовый
SELECT id, ts_rank(tsv, query) AS score FROM note_chunks,
       plainto_tsquery('russian', :q) query WHERE tsv @@ query LIMIT 30;
-- Векторный
SELECT id, 1 - (embedding <=> :vec) AS score FROM note_chunks
       ORDER BY embedding <=> :vec LIMIT 30;
```
Слияние — **Reciprocal Rank Fusion**: `score = Σ 1/(60 + rank_i)`. Топ-8 чанков в контекст, в теге `<data source="notes:<path>#<heading>">`. Ожидаемое время — сотни миллисекунд; замерить на реальной базе.

Ответ по заметкам всегда указывает файл и заголовок: «📄 Проекты/ESP32-заметки.md → «BLE на ESP32», 03.08». На «сделай выжимку» — полный текст релевантных файлов в модель → сводка со ссылками на файлы и заголовки.

## 9. Актуальность знаний

«Быть актуальным» — не значит читать новости. Новости — классическая псевдопродуктивность. Значит: **твои источники и роадмапы не устаревают**.

- `source_freshness` раз в месяц: HTTP-проверка всех ссылок роадмапов + поиск «изменилось ли что-то существенное» по темам активных узлов (новая мажорная версия фреймворка, устаревшее API)
- Результат — не лента, а **максимум 3 пункта в месячном разборе**, каждый с действием: «Новая мажорная версия фреймворка изменила API хуков — в узле "Хуки" заменить источник Y на Z. [Заменить] [Оставить]»
- Без подтверждения ничего в роадмапе не меняется
