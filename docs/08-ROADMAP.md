# 08 · Дорожная карта

## Принцип: польза раньше фич

Главный риск проекта — не техническая сложность, а **смерть на архитектуре**. Она уже случилась один раз: с сентября
по ноябрь — четыре направления (Docker-прототип v1, Docker v2, спецификация 2.0, Lite с сервером) и ни одной недели
ежедневного использования: на 11.11 бот ещё не был привязан к владельцу. Поэтому правило жёсткое:

> **Следующий пункт начинается только после 7 дней подряд, когда предыдущий реально работал на тебе.**
> Не «код написан», а «я этим пользуюсь неделю». Данные журнала решают, что делать дальше, а не идеи.

Размер: **S** — вечер, **M** — 2–3 вечера, **L** — неделя. Один пункт = одна ветка = один PR с тестами и правкой спецификации.

## R0 · Запуск и неделя жизни — сейчас, без кода

То, что может сделать только человек, и без чего всё остальное бессмысленно:
1. Привязать бота: отправить `/start` своему боту (или `arvix setup --telegram --yes`). Если токен где-то засветился —
   сначала `/revoke` у @BotFather.
2. Токен подписки на сервере: `ssh -t arvix@HOST bash ~/.local/share/arvix/app/deploy/server-claude-token.sh`,
   затем `systemctl --user enable --now arvix-telegram` на сервере.
3. Знакомство: блоки «Ядро» и «Распорядок дня» → сохранить распорядок. Остальное — по блоку за вечер.
4. Неделю: отвечать на брифинг сном, нажимать кнопки, проходить разбор.

**Готово, когда:** 7 дней подряд в журнале есть брифинг, хотя бы одна закрытая задача и пройденный разбор
(`arvix events --days 7`).

## Следующее — по очереди

### R1 · Протокол старта · M
**Что.** T+10 после начала, задача не начата и кнопок не было → «Не начал. Что мешает?» с пятью кнопками:
непонятно с чего начать · слишком большое · не хочу · нет сил · другое важнее. На каждую — конкретный приём кодом:
первый шаг на 2 минуты · «только первые 15 минут» · правило 5 минут · чек-ин энергии и замена на лёгкую задачу ·
перенос с причиной (не срыв). Событие `start_blocked(reason_code)`.
**Почему.** Главная точка срыва — начало задачи, а не середина. Наказание за несделанное не помогает начать; разбор
причины и приём — помогают. Коды причин — лучшие данные для ретро: «70 % срывов по алгебре — „непонятно“» значит,
что задачи сформулированы плохо, а не что человек ленивый.
**Затронет.** `telegram/scheduler.py`, `bot.py`, `templates.py`, `core.py`, `rules.py`. **Готово:** тест на всю цепочку
кнопок; ретро видит коды причин.

### R2 · Недельное планирование в Telegram · M
**Что.** Воскресенье после ретро: цифры недели → 1–3 результата следующей недели по главной цели (кандидаты: следующий
узел роадмапа, долг, незакрытое) → проверка ёмкости против бюджета → подтверждение кнопкой. Результаты недели видны
в брифинге и разборе.
**Почему.** Это мост «цель → день». Сейчас он есть только в Claude Code (скилл `plan`), куда человек может не дойти.
**Затронет.** `bot.py` (`run_retro` → предложение), новые события `week_planned`, `context.py`. **Готово:** неделя с
подтверждёнными результатами; в контексте строка «РЕЗУЛЬТАТЫ НЕДЕЛИ».

### R3 · Критерий готовности у задач · S
**Что.** Поле `outcome` (DoD): «5 задач из банка ФИПИ на задание 21 без ошибок» вместо «Математика 90 мин».
Голова и скиллы не создают задачу важности ≥ 3 без DoD; напоминание T−5 и отчёт показывают DoD; разбор сверяет отчёт с DoD.
**Почему.** Задача без результата — бронь времени: отсидел 90 минут = «выполнено», прогресса ноль (П4).
**Затронет.** `core.add_task`, `state.Task`, `brain` (схема), `context.task_line`, шаблоны. **Готово:** тест «важная задача
без DoD от модели — отказ с подсказкой».

### R4 · Повторения: учёт Anki · S → M
Сейчас — блок шаблона «Anki: все карточки на сегодня» ([06-LEARNING.md §5](06-LEARNING.md#5-интервальные-повторения---r4)).
Дальше, если блок неделю живёт: на ноутбуке через AnkiConnect — число повторённых и просроченных карточек за день
событием `srs_reviewed`; просрочка — строкой в брифинге. Свою систему карточек не строить.

### R5 · Приватность головы · S
Защищённые папки хранилища (`[vault] private = ["Дневник", "_private"]`): голова не читает их (правила `deny` для
Read/Grep/Glob), MCP `notes` не отдаёт. Маскирование явных секретов (токены, номера карт) в тексте перед вызовом модели.

### R6 · Квоты: подсказка в четверг · S
Недобранная к четвергу квота → кодом подобрать свободное окно в шаблонах пятницы–воскресенья и предложить блок
кнопкой «Добавить». Сам план без подтверждения не меняется.

### R7 · Понижение частоты — анти-зависимость · S
Если 2 недели подряд задачи сферы начинаются вовремя без напоминания ≥ 90 %, T−5 для этой сферы отключается;
два сорванных старта подряд — включается обратно. Изменение — строкой в ретро. Успех системы — её молчание.

### R8 · Месячное ретро · S
1-го числа: цели (актуальны? метрика двигается?), роадмапы (темп против часов), автонагрузка за месяц, автономность,
профиль (страхи и привычки ещё те?). Сейчас — скилл `retro` вручную.

### R9 · Syncthing вместо rsync · S
Убрать окно конфликта 10 минут и воскрешение удалённых файлов ([07-OPERATIONS.md §4](07-OPERATIONS.md#4-синхронизация-хранилища)).
Syncthing уже ставится на сервер; нужны инструкция, проверка в `doctor` и отключение `arvix-vault-sync.timer`.

### R10 · Голосовые сообщения · ✅ сделано
Groq, OpenAI или локальный whisper.cpp; распознанный текст показывается до обработки
([05-INTERFACES.md §2.6](05-INTERFACES.md#26-голосовые-сообщения)). Дальше — только если журнал покажет нужду:
голосом в Claude Code уже умеет сам Claude Code.

### R11 · ESP32-таймер: связь с журналом · M
Прошивка работает автономно ([10-ESP32-BUILD.md](10-ESP32-BUILD.md)). Связь: HTTP-эндпоинт на сервере для
`session_end` → `focus_session(task_id)` → `K_proof = timer 1.4`. Таймер в Telegram уже пишет то же событие
([05-INTERFACES.md §2.7](05-INTERFACES.md#27-панель-дня-клавиатура-и-фокус-таймер--приложение-внутри-telegram-)); ESP32 — тот же путь с железа.
Делать после сборки устройства и недели его использования офлайн.

### R12 · Напоминание для обязательного блока · S
Опционально для блоков вроде «Репетитор 17:00»: T−5 без «Сделано?», без XP и HP.

## Чего не будет

- Отдельный Android-проект (Kotlin, TWA через Bubblewrap), WebSocket — приложение одно, PWA, его APK собирает Chrome (D26, D31)
- Звонок с ботом в голосовом чате Telegram — Bot API этого не умеет, вместо него режим разговора (D34)
- Автоустановка навыков, плагинов и MCP самой головой — библиотеку пополняет владелец (D33)
- Docker, Postgres, Redis, очереди, несколько LLM-провайдеров, совет из шести моделей
- Фото-верификация (EXIF, перцептивный хэш, vision): трение даёт и одна фраза отчёта
- Мосты к часам и Health Connect, экранному времени, NextDNS, ПК-агент — пока ручной сон закрывает 80 % пользы
- Финансовый модуль сверх учёта трат
- Платформа агента: песочница, самодоработка через PR, Google Диск, YouTube, свои «блокноты» вместо NotebookLM
- Своя система интервальных повторений

Причины — [09-DECISIONS.md §2](09-DECISIONS.md#2-решения). Любой пункт можно вернуть, если журнал покажет, что без него
не работает главное.

## Если застрял

| Симптом | Действие |
|---|---|
| Бот открывается раз в неделю, чтобы отмахнуться | Механика неверна, а не ты слабый: меньше задач в шаблоне, ниже важность, `/silent` чаще. Не терпеть |
| Штрафы бесят | Уменьшить урон (`rules.py`), добавить щитов (`shields_per_month`). Система под тебя, не наоборот |
| Арвикс звучит не так | Править `fewshot.json`, не правила. Конституция меняется редко |
| План не выполняется вторую неделю | Автонагрузка срежет сама; не ждать — `/schedule меньше часов` |
| Пункт дорожной карты идёт больше двух недель | Разрезать: выпустить то, что можно за 2 дня |
| Пропал интерес | Сигнал, что фича длинная, а пользы мало. Вернуться к R0: неделя жизни на том, что есть |
