# 08 · Фазы реализации

## Принцип: работающий цикл раньше красивых фич

Главный риск проекта — не техническая сложность, а **смерть на фичах**: написано много модулей, а базовый цикл «план → напоминание → отчёт → разбор» не работает надёжно ни одного дня. Именно это произошло к ревизии 2.0: ИИ-слой и прошивка ESP32 написаны раньше, чем API, TWA и надёжные напоминания (12-DECISIONS §5).

**Критерий перехода к следующей фазе: предыдущая работает на тебе минимум 7 дней подряд.** Не «код написан» — «я этим пользуюсь неделю, и оно не ломалось».

Порядок фаз выбран по ценности: сначала то, что каждый день ведёт к цели (цикл и планирование), потом обучение, потом интеграции и фоновый анализ, железо — последним и опционально.

## Фаза 1 · Цели и планирование (3 недели)

**Цель:** каждый день работает на цель. Это то, что отличает Арвикса от трекера привычек.

| Блок | Содержание |

## Фаза 6 · Платформа агента (3–4 недели)

Подробно — [13-AGENT-PLATFORM.md](13-AGENT-PLATFORM.md). Принцип: Arvix сам предлагает и готовит новые возможности, включает их твоё одобрение, всё откатывается через git.

| Блок | Содержание |
|---|---|
| Песочница | Отдельный контейнер без БД и секретов, `sandbox_exec`, лимиты, пересоздание |
| Самодоработка через PR | Код + тесты в песочнице → PR в свой репозиторий → твой мерж. Branch protection на `main` |
| Ops белым списком | Статус, логи, бэкап (auto); перезапуск, деплой, восстановление (confirm). Мониторинг сервера |
| Скиллы | `skills/*/SKILL.md`, `load_skill`, `propose_skill`, одобрение в TWA |
| `MEMORY.md` | Читаемая память в Obsidian, двусторонняя синхронизация с `memory_facts` |
| Правки промпта | Ядро неизменяемо; голос и few-shot — через дифф + гейт тестов |
| Коннекторы и плагины | Поиск и карточка одобрения MCP-серверов, токены вводишь ты, `plugins/*` |
| Google Диск, YouTube | Drive API (чтение auto, запись confirm), YouTube Data API + транскрипты с честным фолбэком |
| Блокноты источников | Замена NotebookLM: ответы только по источникам со ссылками |
| Obsidian: полный доступ | Правка везде с коммитом на изменение, `.trash/`, защищённые папки, вечерняя сводка с откатом |
| Точность | Проверка утверждений, контрольный набор (~50 вопросов), кнопка [Неверно], журнал ошибок |

**Готово, когда:** Arvix сам предложил и (после одобрения) добавил хотя бы один скилл и один инструмент через PR; блокнот по реальному предмету отвечает со ссылками и честно говорит «нет в источниках»; неделю правит хранилище, и каждое изменение можно откатить одной кнопкой; контрольный набор проходит после каждой правки.

Можно начать раньше (после фазы 1) только с песочницы и PR-модели — если очень хочется, чтобы Arvix писал себе инструменты.

## Что делать, если застрял

| Симптом | Действие |
|---|---|
| Фаза идёт вдвое дольше плана | Найти, что можно выбросить из фазы и выпустить за 2 дня. Остальное — в следующую фазу |
| Не заходит интеграция (Huawei, Obsidian, MCP-сервер) | Таймбокс 1 день. Не получилось — fallback и дальше |
| Разбор превращается в повинность | Сократить до 3 шагов: факты → план на завтра → подтверждение. Вопросы — через день |
| Напоминания бесят | Не терпеть: сократить до T+0 и конца блока, T−5 отключить. Система под тебя |
| Бот звучит не так | Править **few-shot**, не конституцию |
| Пропал интерес | Сигнал, что польза не видна. Вернуться к недельному планированию: если цель на неделю не ясна — бот бесполезен |
| Агент делает больше одного шага | Остановить, откатить лишнее, вернуться к правилу «один шаг = один коммит» |
