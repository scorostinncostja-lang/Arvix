# 06 · Обучение и второй мозг

## 1. Принцип

«Не понимаю, как, где и откуда учиться» — это не недостаток информации, а недостаток структуры: информации избыток,
поэтому паралич. Arvix даёт структуру и проверку, но **не делает работу понимания за человека**: готовый текст от ИИ
даёт ощущение знания без знания (П2).

Учебный цикл:

```
цель (ОГЭ: математика 5) → этап с датой и метрикой → роадмап по методу человека
  → ближайший узел = блок глубокой работы в распорядке → первоисточник → самостоятельная работа
  → чекпоинт (объяснить / решить / сделать) → узел закрыт → повторения → следующий узел
```

Где что живёт: цели и этапы — журнал (`goal_set`) и `05_System/Цели/`; роадмапы и каркасы конспектов — хранилище
Obsidian; блоки — шаблоны дней; учебные вопросы — события `learning_question`. Скиллы: `goal`, `learn`, `notes`.

## 2. Сократовский режим ✅

Граница: **навык, который человек строит** (предмет, язык, программирование) — учитель с наводящими вопросами.
План, поиск по его заметкам, настройка, организационное — Arvix помогает прямо.

На учебный вопрос первым сообщением — не ответ, а:
- направление мысли и один наводящий вопрос;
- 2–3 источника, **первоисточник первым**: учебник и параграф, официальная документация, спецификация;
- оценка времени: «20 минут сам»;
- «потом объяснишь мне своими словами».

| Ситуация | Поведение |
|---|---|
| Тема есть в роадмапе | подсказка + узел и его источник |
| Ответ уже есть в заметках человека | «Это есть у тебя: `<файл>`. Перечитай» — без пересказа |
| Повторный вопрос по той же теме | указать на повтор, предложить практику |
| `/answer` в Telegram или «дай ответ» | полный ответ с источниками; событие `learning_question(mode=direct)` |
| Идёт рабочий блок | «Не сейчас — записал в Inbox, разберём после блока» |

Каждый учебный вопрос пишется событием (`hint` или `direct`) — из них считается автономность: доля вопросов без
готового ответа ([02-MECHANICS.md](02-MECHANICS.md), [00-VISION.md §5](00-VISION.md#5-механика-анти-зависимости-функционал-а-не-декларация)).
Штрафа за `/answer` нет: это метрика, а не наказание.

### 2.1. Правило первоисточника
Обучающий ответ без названного первоисточника перегенерируется валидатором ([04-AI-LAYER.md §6](04-AI-LAYER.md#6-валидаторы-ответа-l0-без-модели)).
Ссылка — только настоящая. Не уверен в адресе — источник без ссылки: выдуманный URL хуже его отсутствия.

Первоисточники по умолчанию:
- **ОГЭ / ЕГЭ** — демоверсия, спецификация и кодификатор ФИПИ на текущий год, открытый банк заданий ФИПИ;
  теория — школьный учебник с параграфом;
- **программирование** — официальная документация (MDN, docs.python.org…), затем книги и курсы;
- **языки** — словарь и грамматический справочник уровня, затем подкасты и тексты.

## 3. Роадмап ✅ скилл `learn`

Роадмап — чеклист узлов в хранилище: в папке предмета (`02_Areas/<Предмет>/Роадмап — <тема>.md`, ссылка — в карту
предмета `00_<Предмет>.md`) или в `[vault_paths] roadmaps`. В начале файла — цель и этап, которым он служит.

```markdown
- [ ] Задания 20–22: уравнения и неравенства — зачем: 6 баллов второй части · 8 ч · зависит от: задания 9, 13
  - Первоисточник: демоверсия ФИПИ 2027, задания 20–22 + кодификатор, раздел 3 · 1 ч
  - Теория: Макарычев, 9 класс, §§ 12–14 · 2 ч
  - Практика: открытый банк ФИПИ, 15 задач этого типа · 5 ч
  - Чекпоинт (test): 5 новых задач подряд без ошибок, оформление как на экзамене
```

Жёсткие требования к узлу:
1. **первоисточник** — хотя бы один официальный документ или учебник, не только видео и статьи;
2. **оценка часов** — чтобы узел можно было положить в бюджет недели;
3. **зависимости** — что без чего не имеет смысла;
4. **проверяемый чекпоинт**: `explain` — объяснить своими словами, `test` — решить N задач, `build` — сделать вещь;
5. **метод человека.** Перед роадмапом Arvix читает его заметки о том, как он учится (например, `03_Resources/Обучение/`:
   Фейнман, свой «универсальный метод»), и строит чекпоинты по ним: у Фейнмана чекпоинт каждого узла — объяснить
   простыми словами без подглядывания.

Ближайший узел — в план: блок глубокой работы в часы пика энергии (скилл `plan` или шаблон). Ревизия роадмапа —
раз в месяц в ретро: порядок, источники, оценки часов против факта.

### 3.1. Чекпоинт «объясни»
Человек отметил узел пройденным → «Объясни мне это, как объяснил бы однокласснику, 3–4 предложения» → до трёх
уточняющих вопросов → оценка: что верно, что пропущено, что дочитать (конкретный раздел, 10 минут). Узел закрывается
только после верного объяснения. Если человек сам ставил галочки, файл стал его: Arvix дописывает отметку или
спрашивает разрешения перезаписать.

## 4. Подготовка к экзамену (ОГЭ, ЕГЭ, контрольные) ✅ скилл `learn`

Экзамен — лучший случай для системы: результат измерим, формат известен заранее, первоисточник один.

1. **Диагностика.** Вариант по демоверсии **на время**, в условиях экзамена. Разбор по номерам заданий: таблица
   «номер — балл — тип ошибки (не знаю / знаю, но ошибся / не успел)». Это и есть стартовая точка цели.
2. **Цель и этапы.** Цель — оценка или балл к дате экзамена. Этапы по 3–6 недель с метрикой в баллах пробника:
   «к 15.12 — задания 1–12 стабильно, пробник ≥ 15 первичных».
3. **Роадмап по слабым номерам.** Узел — номер задания или группа номеров. Источник — кодификатор и демоверсия,
   теория — учебник с параграфом. Чекпоинт — `test`: N новых задач этого номера из открытого банка подряд без ошибок.
4. **Еженедельный вариант на время** — в выходной, отдельным блоком глубокой работы. Баллы пробника — главный
   опережающий показатель цели; записываются фактом (`remember`, тема `learning`) и в файл цели.
5. **Повторения** — §5. Ошибки пробника → карточки.
6. **Разбор недели** (ретро): какие номера просели, хватает ли часов до экзамена по темпу. Не хватает — сузить
   цель или добавить часы, решает человек.

## 5. Интервальные повторения — 📋 R4

Без повторений выученное забывается за недели; эффект тестирования и распределённого повторения — самые надёжные
результаты когнитивной психологии. Своей системы карточек в Arvix **нет и строить её не нужно**: Anki с алгоритмом
FSRS делает это лучше. Как подключить сейчас, без кода:
- шаблон дня: блок «Anki: все карточки на сегодня», 15–20 минут, важность 2 (кнопка ✅), лучше утром;
- карточки делает **сам человек** из своих ошибок и конспектов — формулировка карточки и есть работа понимания;
- в ретро — вопрос, были ли дни с просроченными карточками.

Учёт повторений из Anki автоматически — R4 в [08-ROADMAP.md](08-ROADMAP.md).

## 6. Каркас конспекта, а не конспект ✅ скилл `notes`

«Сделай заметку про производные» → Arvix создаёт **каркас**, который человек заполняет сам:
вопросы, на которые нужно ответить своими словами, первоисточники с минутами, пустой раздел «Мои ответы»,
чекпоинт. Место — `02_Areas/<Предмет>/Конспекты/<Тема>.md` или `[vault_paths] notes`; ссылка — в карту предмета.
Конспект целиком — только по явному «/answer» или «напиши за меня», с пометкой в начале файла
«Сгенерировано Arvix, не проверено мной».

## 7. Obsidian как второй мозг

### 7.1. Поиск ✅
`notes` action=`search`, `/find`, `arvix find`: по основам слов (слово длиннее 5 букв обрезается на 2 последние —
грубая поддержка русских окончаний), вес — число совпавших основ, частота и совпадение с именем файла. Результат —
путь, ближайший заголовок, дата, кусок текста. Выжимка — по прочитанным файлам со ссылками `[[Заметка#Заголовок]]`,
без пересказа того, чего в заметках нет. Векторного поиска нет — на сотнях заметок он не окупается ([09-DECISIONS.md](09-DECISIONS.md) D2).

### 7.2. Ежедневный отчёт ✅
- **Утро** (брифинг или `notes` action=`daily_sync`): заметка дня создаётся по шаблону человека — папка, формат имени
  и шаблон из настроек Daily notes Obsidian или `[vault_paths]`. Переменные шаблона подставляются так, как это сделал
  бы Obsidian: ядро (`{{date}}`, `{{date:DD.MM.YYYY}}`, `{{time}}`, `{{title}}`, формат moment.js, русские названия) и
  Templater (`<% tp.date.now("D MMMM", 1) %>`, `<% tp.file.title %>`). Заполняются дата, номер дня и недели программы,
  задачи чекбоксами. Заметка, где переменные остались сырыми (17.11: `date: {{date:YYYY-MM-DD}}`), чинится сама при
  первом тике дня.
- **Задача закрыта** (кнопкой, словами, в приложении) — код ставит `[x]` у её строки в заметке дня. Свои строки код
  узнаёт по началу «время название (N мин)», чужие чекбоксы не трогает.
- **День**: поля, которые человек заполнил сам (телефон, игры, срывы, энергия), Arvix читает в брифинге и разборе
  вместо переспрашивания.
- **Вечер** (после разбора): заполняются **только пустые** поля frontmatter и только те, что есть в шаблоне (`sleep`,
  `wake`, `focus_min` / `focus_minutes` — после разбора и 0, `workout`) и блок «Итог дня · Arvix» между метками
  `%% arvix:день %%` (комментарий Obsidian — человеку не виден). Блок — для человека: что было за день и почему
  («Плана не было: распорядок ещё не сохранён…»), глубокая работа против нормы, фокус-сессии, сон против нормы, отчёты
  закрытых задач и **вывод Arvix**. Ответы человека на разбор в заметку не копируются — они в журнале (память
  Arvix). Старые HTML-метки `<!-- arvix:… -->` заменяются при первой записи.

### 7.3. Правила записи
Создаёт свои заметки где угодно, чужие только дополняет или обновляет свой блок, перезаписывает только по явному
«да» с копией в `_backup`, удалять не умеет. Подробно — [03-DATA-MODEL.md §5](03-DATA-MODEL.md#5-obsidian--второе-хранилище).

### 7.4. Синхронизация
Хранилище живёт на ноутбуке; в удалённом режиме копия на сервере синхронизируется `rsync` раз в 10 минут —
[07-OPERATIONS.md §4](07-OPERATIONS.md#4-синхронизация-хранилища). Голова бота читает хранилище только на сервере,
где она запущена.

## 8. Учебный блок в Telegram ✅

Запуск словами (D23): «давай позанимаемся физикой 45 минут» → карточка блока — что, сколько, когда, прошлый урок — и
кнопки «📚 План урока» · «🎯 Просто таймер» · «✖️ Не сейчас». План (вызов головы) готовится только по кнопке. Учебной
задачи на сегодня нет — она создаётся. По расписанию (T+0) план приходит сразу, как и раньше.

Задача сферы `learning` в распорядке — не «бронь 45 минут», а урок: Arvix сам смотрит роадмап, берёт следующий
узел, раскладывает блок по минутам под инструменты человека и в конце проверяет. Объяснение «у доски» — когда человек
спрашивает внутри блока. Код: `arvix/lesson.py`, `telegram/bot.py` (`prepare_lesson` … `grade_lesson`); решение —
[09-DECISIONS.md D22](09-DECISIONS.md).

```
T+0 (или ▶️ / 🎯 / /learn) → голова №1: роадмап, журнал ошибок, метод человека, прошлые уроки → план
  📚 Физика: постоянный ток · 45 мин
  Закон Ома для участка цепи · Зачем: ОГЭ физика №8 · Роадмап: Постоянный ток (3/12)
  План: 0–5 вспомнить с пустого листа · 5–20 Перышкин §44–45 + NotebookLM: выжимка · 20–35 Решу ОГЭ №8, 5 задач
        · 35–42 заметка своими словами (Obsidian) · 42–45 проверка: 3 вопроса
  Источники: Перышкин, 8 класс, §44 · открытый банк ФИПИ, физика, №8 · заметка о методе
  📝 Каркас заметки: 06_Feyn Concept/Закон Ома.md            [▶️ Начать · 45 мин]
▶️ → task_started → таймер на всю длительность (05-INTERFACES §2.7); вопросы в блоке → L1 с <lesson>: объяснение по шагам
таймер вышел → focus_session(45, task) → «Проверка — 3 вопроса, ответь одним сообщением» (await lesson_check)
ответ (текст или голос) → голова №2: оценка по эталонам → feedback и квитанция одним сообщением:
  ✅ задача — записал · проверка 67% · «В карточки и журнал ошибок: …» · 📝 заметка
→ lesson_checked(score, gaps) → complete_task(done_pct = max(30, score), report = ответы)
```

Правила:
- **Тема — из роадмапа**, следующий незакрытый узел после прошлых уроков (`Core.lesson_history`, строка УРОКИ в контексте
  и в промпте). Роадмапа нет — тема по цели (для ОГЭ — кодификатор ФИПИ), и голова говорит об этом в «Зачем».
- **План по методу человека**, а не общий: голова читает его заметки о методе (`03_Resources/Обучение`: желательная
  трудность, вспоминание с пустого листа, Фейнман, интерливинг) и его инструменты — учебник с параграфом, NotebookLM
  (выжимка, 5 вопросов), видео по названию, Решу ОГЭ / банк ФИПИ с номером задания, Gemini только для сократовского
  вопроса при затыке, Obsidian, Anki. Новых инструментов не навязывает; дополнить список — `[learning] tools`.
- **Первый шаг — вспомнить с пустого листа, последний — проверка**: 3 вопроса (`[learning] check_questions`) на понимание
  и применение, один — задача; у каждого эталон, который человек не видит. Ответ на проверку **и есть отчёт** —
  «Сделано?» для такого блока не приходит. ▶️ не нажат (учился без таймера) — проверка всё равно приходит в конце блока
  по плану (D53); без этого блок молчал и в 04:00 уходил в долг. Идёт таймер — проверку присылает конец таймера.
- **Каркас заметки** создаёт код по шаблону человека (`Templates/Concept.md`: название, предмет, дата, вопросы
  самопроверки, источники; остальное он пишет сам) в папку концептов (`[learning] concept_dir`, иначе папка с «concept»
  в названии, иначе `[vault_paths] notes`). Существующая заметка не трогается.
- **Объяснение у доски** (`lesson.LESSON_CONTEXT`): пока блок идёт, вопрос по теме получает подробное объяснение по шагам
  с примером и одним вопросом на понимание — порцией на 2–3 минуты чтения, не параграфом целиком; задачу за человека
  не решает (один шаг и «что дальше?»); первоисточник называется. Это не обходит сократовское правило: человек сначала
  работает с источником по плану, а объяснение просит там, где застрял. Вопрос не по теме — одной строкой и назад к блоку.
- **Оценка честная**: пустой ответ или «не знаю» — 0 за вопрос; `done_pct` закрытия = оценка, но не ниже 30 — время
  блока отсидено (П4: результат выше активности, но сорок пять минут с источником — не ноль). Таймер шёл на всю
  длительность — это видно в журнале (`focus_min`).
- **Пробелы** (`gaps`) приходят формулировкой для карточки Anki и журнала ошибок — записать их туда остаётся
  ритуалом человека (§5). Следующий блок получает их через УРОКИ и ленту событий; ретро видит оценки по предметам.
- **Голова недоступна** в начале — запасной план кодом (те же фазы по минутам, тема по названию задачи), проверки нет,
  в конце обычное «Сделано?»; ✅ на нём — сразу просьба об отчёте, а не второй «Сделано?» (D53). Недоступна в конце — ответы записаны, блок закрыт как сделанный, оценки нет.
- `/learn` — урок по ближайшей учебной задаче дня; `/learn 30 Информатика: Python циклы` — новый блок прямо сейчас.
  `[learning] auto_lesson = false` возвращает обычное «Блок пошёл» для учебных задач.

Рабочий стол урока с окнами (тест, доска, схема, видео) — раздел «Обучение», §10.

Тесты: `tests/test_telegram.py::LessonTest` — план из роадмапа и каркас заметки, полный цикл «таймер → проверка →
оценка → закрытие», история уроков в промпте и запасной план без головы, `/learn` и выключение.

## 10. Раздел «Обучение» ✅ (D55)

Пятая вкладка приложения (Ctrl+5). **Своей модели обучения нет:** учебная сессия — это учебный блок (задача сферы
`learning`) и его урок из §8 — план по минутам, таймер, проверка. Раздел добавляет к уроку рабочий стол с окнами и
собирает в одно место всё учебное. Код: `arvix/study.py`, `web/api.py::study_view`, `app.js` (`renderStudy`).

**Обзор.** Учебные блоки дня («Начать сессию» / «Открыть» / «Посмотреть»); очередь «Что выучить» по проектам и целям —
у темы вид *теория* (понять и объяснить) или *практика* (сделать руками: задачи, код, упражнение), «Учить сейчас» ставит
блок в свободное окно и сразу готовит сессию, «Уже знаю» — тема пройдена; «Пройдено» — уроки с оценкой проверки и
пробелами для карточек, по предметам — сколько блоков и средняя оценка (факты, не очки, D41).

**Рабочий стол сессии.** Слева окна, справа чат урока (на телефоне — «Стол | Чат с Arvix»). Чат — своя нить
сессии (`message_in/out.study` = id учебной задачи, D56): голова получает историю нити, без приветствия дня; в общем
чате нити нет. Раньше чат урока был общим чатом с начала урока, и незакрытый вечером урок показывал разбор дня и «ложись».

| Окно | Что | Кто проверяет |
|---|---|---|
| План | шаги по минутам; текущий подсвечен по таймеру | — |
| Тест (`quiz`) | вопросы с вариантами — сразу ✓/✗, верный ответ и «почему»; открытые — своими словами | варианты — код, открытые — голова на проверке блока |
| Доска (`board`) | графики `y = f(x)`, точки, отрезки, окружности, многоугольники; один масштаб по осям — круг остаётся кругом | — (формулу разбирает свой парсер, без `eval`) |
| Схема (`diagram`) | узлы и стрелки, слоями от корня | — |
| Видео (`video`) | YouTube / RuTube / Vimeo встраиваются; другая ссылка — ссылкой; нет настоящей ссылки — поиск по запросу и вопрос «после просмотра» | — |
| Объяснение (`text`) | порция «у доски» на 2–3 минуты | — |
| Заметка | каркас конспекта урока из хранилища: человек пишет здесь же, сохраняется в Obsidian с защитой от затирания | — |
| Источники | первоисточник первым | — |
| Проверка | вопросы конца блока и поле ответа; ответ и есть отчёт (§8) | голова №2 |

**Кто ставит окна.** Arvix: 0–3 окна в плане урока (`LESSON_SCHEMA.panels`) и по ходу — действием `study_panel` из чата
сессии («нарисуй график», «дай тест», «схема темы»; ошибка в тесте → разбор и новый вопрос). Тот же `id` — замена окна,
`hidden` — скрыть. Человек сам добавляет только видео по ссылке (и скрывает любое окно); тест и доску он не пишет себе
сам — их ставит Arvix. Окно проверяет код (`study.clean_panel`): тест без эталона, формула с чем-то кроме чисел, `x` и
известных функций, видео без `http(s)` — отказ в квитанции, а не битое окно. Окон не больше 12.

**Что видит Arvix.** С каждым вопросом из сессии голова получает блок `<study>` (`study.context_block`): какие окна
открыты, ответы на тесты по вопросам (верно / ошибка / открытый с эталоном), **текст заметки, который человек уже
написал**, и сколько прошло. Экрана он не видит — видит то, что записано: это честнее и не следит за человеком.
Эталоны теста и проверки в приложение не уходят, пока человек не ответил (`study.public_panel`).

**Связь с проектами.** Очередь одна — события `learn_item_set` (`projects.set_learn`): тема проекта сразу в «Обучении»,
выученная в «Обучении» — ✓ в проекте; «Учить сейчас» в проекте открывает сессию в «Обучении». Тема из очереди задаёт
урок (`study.lesson_hint`): голова не ищет тему в роадмапе, а для практики отдаёт большую часть блока работе руками.
Название блока «Учить: тема» / «Практика: тема»; предмет урока — сама тема, а не слово «Практика» (`lesson.subject_of`).

**Правила.**
- Один урок за раз: пока идёт урок одной задачи (таймер или ждёт ответа на проверку), сессию другой не открыть —
  проверку нельзя потерять.
- «Готов к проверке» — закончить раньше: прошедшие минуты записываются, приходят вопросы.
- Закрытая сессия — история: стол без чата, итог проверки, пробелы, ответы тестов.
- В 🟥 и при выключенном менторе раздел пуст: одна строка без плана, теста и таймера (правило №5).
- Видео — источник, а не замена работы: у окна видео вопрос «после просмотра», первоисточник — учебник (§2.1).
- Заметку Arvix не пишет: каркас, а слова — человека (§6).

Тесты: `tests/test_study.py` — окна и их проверка, тест кодом, эталоны не утекают, Arvix видит ответы и заметку,
окно из чата, проверка блока учитывает тесты, тема проекта не теряется, второй блок по теме не ставится, HTTP целиком.
