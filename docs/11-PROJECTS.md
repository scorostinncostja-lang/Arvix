# 11 · Проекты 📋

> Стартапы, сервисы, бизнесы, свои продукты — то, что строится вместе с Арвиксом ради денег, навыка и опыта.
> **Статус: 📋 запланировано** ([08-ROADMAP.md](08-ROADMAP.md) R13, решение [D43](09-DECISIONS.md)). В коде этого нет.
> Документ — проект спецификации: при реализации он переписывается под код.

## 1. Принцип: проект — это ставка

Проект — не «то, чем я занимаюсь», а **ставка**: гипотеза, бюджет часов и денег, метрика, которую нельзя накрутить,
и заранее записанный критерий закрытия. Закрытие по критерию — нормальный исход, а не провал (вопрос 4 фильтра).

Три правила сверх общих шести:

1. **Начинает человек.** Арвикс может предложить идею с доказательствами из журнала, но проект становится активным
   только после «да» (П2). Арвикс сам проекты не запускает.
2. **Решает и думает человек.** Арвикс собирает факты с источниками (конкуренты, цены, законы) и задаёт вопросы.
   Гипотезы, выводы и решения пишет человек. Арвикс не пишет за него код, тексты и планы (анти-цели, [00-VISION.md §7](00-VISION.md#7-анти-цели)).
3. **Главная цель важнее.** Часы проекта — отдельный канал с потолком; проект никогда не вытесняет блоки главной цели
   (сейчас — ОГЭ). Потолок ставит код, а не обещание модели (П3).

## 2. Жизненный цикл

| Стадия | Срок | Что на выходе | Переход |
|---|---|---|---|
| 💡 **Идея** | без срока | одна строка в инбоксе идей | не раньше чем через **7 дней остывания** и только по «да» → разведка |
| 🔍 **Разведка** | 1–2 недели, ≤ 3 ч/нед | 10 разговоров с потенциальными клиентами или страница фактов с источниками | «да» → эксперимент; «нет» → закрыт |
| 🧪 **Эксперимент** | 2–4 недели | гипотеза → метрика → результат | метрика сдвинулась → рост; нет → разворот (новый эксперимент), заморозка или закрытие |
| 📈 **Рост** | пока работает | деньги, пользователи, выпущенные версии | пересмотр раз в месяц (R8) |
| ❄️ **Заморожен** | без срока | запись причины | «разморозить» — снова эксперимент |
| ⚰️ **Закрыт** | — | постмортем | — |

Переходы считает код (`stage` в событии, даты, метрика); формулирует и предлагает их модель; решает человек кнопкой.

## 3. Карточка проекта

Без карточки проект не создаётся — как цель без «зачем» ([скилл `goal`](../arvix-claude/skills/goal/SKILL.md)).

| Поле | Пример | Зачем |
|---|---|---|
| `title` | «Бот проверки задач ОГЭ» | — |
| `why` | связь с мечтой или главной целью, словами человека | держит в плохие дни |
| `hypothesis` | «школьники платят 200 ₽/мес за бота, который проверяет задачи 21–25» | что именно проверяем |
| `metric` | «платящие пользователи» | только ненакручиваемое — §4 |
| `kill_criterion` | «к 15.01 меньше 3 платящих — закрываю или разворачиваю» | пишется **до** старта, пока человек не влюблён в идею |
| `hours_cap` | 5 ч/нед | потолок канала `project` |
| `money_cap` | 3000 ₽ | сумма, которую не жалко потерять; сверх — трата только по явному «да» |
| `skills` | Python, продажи, разговоры с клиентами | 1–3 навыка; прогресс — артефакт, не очки (D41) |
| `deadline` | дата конца текущей стадии | — |

## 4. Метрики

Главные — то, что нельзя накрутить без реальной работы (П4, вопрос 2 фильтра):
- деньги от незнакомых людей (не от родителей и друзей);
- платящие или вернувшиеся пользователи;
- выпущенные версии (ссылка на то, чем можно пользоваться);
- проведённые разговоры с клиентами (с записью «что узнал»).

Индикаторы, но не цель: часы, число заметок, число задач. Их Арвикс показывает, но прогрессом не называет.

Цена часа кодом: `(доход − расход) / часы проекта` — «23 ч, +400 ₽ → 17 ₽/ч». Это не оценка человека, а факт для
решения «продолжать ли».

## 5. Роли Арвикса

| Роль | Что делает | Слой |
|---|---|---|
| **Бухгалтер** | часы по проекту из закрытых задач, доходы и расходы, цена часа, остаток `money_cap` | L0 |
| **Планировщик** | блоки проекта в недельном плане внутри `hours_cap`; при нехватке часов срезается проект, а не главная цель | L0, после R2 |
| **Разведчик** | по расписанию ищет конкурентов, цены, похожие кейсы → `Разведка.md` с источниками и пометкой «собрал Арвикс» | L2, не в цепочке ответа |
| **Адвокат дьявола** | на старте — пре-мортем: «прошло 3 месяца, проект умер — почему?»; ответы пишет человек | L1 |
| **Интервьюер** | вопросы для разговоров с клиентами; после разговора — «что узнал, что это меняет» | L1 |
| **Судья** | в воскресном ретро: сдвинулась ли метрика, сработал ли критерий; 3 недели без движения → «Развернуть / Заморозить / Закрыть» | L0 считает, L1 формулирует |
| **Архивариус** | постмортем при закрытии; портфолио закрытых проектов с фактами | L1 |

## 6. Журнал решений

Каждое крупное решение — событие: что решил, какие были варианты, чего ожидаешь, когда проверить
(«беру Telegram-бота, а не сайт — ожидаю 50 пользователей за месяц, проверка 20.12»). В дату проверки Арвикс
спрашивает: «Ожидал 50, вышло 6 — в чём ошибся?» Ответ — событие `decision_reviewed`.

Так ошибки становятся данными ([00-VISION.md §1](00-VISION.md#1-проблема), п. 6), а человек учится точнее прогнозировать —
навык, который остаётся без бота (вопрос 5 фильтра).

## 7. Предохранители (код)

- **Не больше одного активного проекта** (стадии разведка–рост), пока активна главная цель с дедлайном. Конфиг
  `[projects] max_active = 1`.
- **🟥 → проекты на паузе:** блоки проекта не попадают в план, напоминаний нет (как всё необязательное).
- **Экзаменационное окно:** `[projects] freeze = ["2027-04-01", "2027-06-30"]` — проекты замораживаются сами,
  блоки уходят из плана.
- **Деньги:** только учёт. Никаких инвестиций, крипты, займов и советов по ним (анти-цели). Юридический вопрос
  (ограничения ИП и самозанятости до 18 лет) Арвикс называет и даёт первоисточник (nalog.ru); решает человек с родителями.
- **Инбокс идей не превращается в работу:** «идея: …» — одно событие без задач и исследований до решения о старте.

## 8. Данные (черновик)

| Событие | Поля | Примечание |
|---|---|---|
| `goal_set` | `kind=project` + `hypothesis, kill_criterion, hours_cap, money_cap, skills, stage` | новой таблицы нет: проект — цель (D43) |
| `task_created` | + `project_id` | часы проекта = свёртка закрытых задач |
| `expense_logged` | + `project_id` | существующие траты с тегом |
| `income` | `amount, currency, project_id, note` | новое |
| `idea_captured` | `text` | инбокс идей |
| `project_decision` | `project_id, decision, options, expected, review_on` | журнал решений |
| `decision_reviewed` | `decision_id, actual, lesson` | — |
| `project_closed` | `project_id, reason, lessons` | постмортем; статус цели — `done` или `dropped` |

Канал нагрузки `project` в `load.py` (`CHANNELS`), с потолком из `hours_cap`, а не из автонагрузки.

## 9. Obsidian

Папка проекта в разделе Projects хранилища (PARA; путь — `[vault]`):

```
<Projects>/<Имя проекта>/
  README.md        карточка: поля §3, стадия, цифры (блок arvix, пишет код)
  Разведка.md      факты с источниками; что собрал Арвикс — помечено
  Эксперименты.md  гипотеза → метрика → результат, по эксперименту
  Решения.md       журнал решений с проверками
  Постмортем.md    при закрытии: что сработало, что нет, что дальше
```

Правила записи — общие ([03-DATA-MODEL.md](03-DATA-MODEL.md)): свою заметку Арвикс перезаписывает, только если человек
её не менял; иначе дописывает.

## 10. Порядок реализации

0. **Без кода:** один реальный проект две недели на том, что есть (скилл `goal`, папка в Obsidian, `/spend`).
   Записать, где неудобно — это и есть требования.
1. **M:** карточка (`kind=project`), `project_id` у задач и трат, `income`, часы и деньги кодом, канал с потолком,
   предохранители §7; скилл `project` в Claude Code, карточка в Telegram.
2. **S:** проекты в воскресном ретро, кнопки «Развернуть / Заморозить / Закрыть».
3. **S:** журнал решений с датой проверки.
4. **M:** фоновая разведка по расписанию (L2).
5. **Если журнал покажет нужду:** инбокс идей с остыванием, портфолио.

Шаги 1–5 — после R1–R3: без недельного плана (R2) планировщику некуда встраиваться, без критерия готовности (R3)
задачи проекта станут бронью времени.
