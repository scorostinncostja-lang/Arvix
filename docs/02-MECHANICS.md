# 02 · Механики

## 1. Задача — базовая единица

```yaml
Task:
  id: uuid
  title: str
  sphere: learning | work | sport | social | health | finance | project | chore
  importance: 1..5          # 5 = провал = провал дня
  difficulty: 1..5          # субъективная сложность
  planned_start: datetime
  planned_duration_min: int
  deep_work: bool           # считается ли в бюджет глубокой работы
  proof: none | confirm | report | photo
  status: planned | active | done | failed | skipped | deferred | debt
  actual_start / actual_end: datetime | null
  quality: 1..5 | null      # самооценка выполнения
  source: user | arvix | quota | debt | recurring
```

### Уровень подтверждения (`proof`) — определяется автоматически

| Условие | proof | Что спрашивает бот |
|---|---|---|
| importance ≤ 2 | `confirm` | Две кнопки: ✅ / ❌ |
| importance 3 | `report` | «Как прошло?» — свободный текст, 1 предложение минимум |
| importance ≥ 4 или sphere = sport | `photo` | Фотоотчёт + текст |
| deep_work = true | `report` + данные таймера | Сверка с фокус-сессиями ESP32/TWA |

Уровень можно поднять вручную, понизить — нельзя.

### Проверка фотоотчёта — что реально делается

Vision-модель **не может** доказать, что ты отжался. Честная постановка задачи:

1. **EXIF-время** — снято в окне задачи ±30 мин. Нет EXIF → флаг подозрения
2. **Перцептивный хэш** (pHash) против всех прошлых фото — не дубликат и не пересъём того же кадра
3. **Релевантность** (1 vision-вызов) — на фото то, что ожидалось по задаче
4. При двух флагах — Арвикс не обвиняет, а **задаёт уточняющий вопрос** и помечает событие `proof_suspicious`

> **Формулировка в конституции:** цель фотоотчёта — трение и ритуал, а не верификация. Соврать можно. Но это будет записано, и Autonomy Score от этого не вырастет. Систему обманывать бессмысленно — она не начальник, она зеркало.

## 2. Опыт, уровни, сезоны

### XP

```
XP = base × K_diff × K_imp × K_proof × K_time

base        = 10
K_diff      = {1:0.6, 2:0.8, 3:1.0, 4:1.4, 5:2.0}
K_imp       = {1:0.7, 2:0.9, 3:1.0, 4:1.3, 5:1.6}
K_proof     = confirm 1.0 | report 1.1 | photo 1.3 | timer-verified 1.4
K_time      = 1.0 если начал в окне ±15 мин; 0.8 если опоздал >15 мин; 1.15 если начал раньше плана
```

Бонусы:
- `+25 XP` — день закрыт на 100%
- `+15 XP` — сон в норме (по данным или ручному вводу)
- `+40 XP` — недельная квота сферы закрыта
- `+50 XP` — тихий день пройден с выполнением ≥70%
- `×1.5` на весь день — если это день типа `Рабочий` (пт-вс) и план всё равно выполнен

### Уровни
`Уровень N → N+1` требует `100 + 20×(N-1)` XP. Уровень **никогда не теряется** — это накопленная история, а не валюта.

### Сезоны (заменяют потерю уровня)

Сезон = 5 недель. В начале — ранг `Бронза`. Внутри сезона копится **Очко Сезона (SP)**:

```
SP за день = (выполнение% × 0.6) + (сон_норма × 0.2) + (глубокая_работа_норма × 0.2)
```

| Ранг | Средний SP за сезон |
|---|---|
| Бронза | < 45 |
| Серебро | 45–59 |
| Золото | 60–74 |
| Платина | 75–87 |
| Элита | ≥ 88 |

В конце сезона: ранг фиксируется в истории, новый сезон стартует с ранга **на одну ступень ниже достигнутого** (защита от почивания на лаврах). Элита → старт с Платины. Провал сезона (Бронза) → следующий сезон с усиленным режимом: минус 20% задач, фокус на одну сферу до восстановления.

**Почему не потеря уровня:** механика, которая одним провалом обнуляет месяц, приводит к удалению приложения. Это доказано в игровом дизайне. Сезоны дают то же ощущение риска без обесценивания.

## 3. Здоровье (HP) — реагирует на тренд, не на событие

Старт: **100 HP**. Регенерация: `+8 HP` за каждый день с выполнением ≥70% и нормальным сном.

### Урон

| Событие | Урон |
|---|---|
| Пропуск задачи importance 1–2 | −2 |
| Пропуск задачи importance 3 | −5 |
| Пропуск задачи importance 4–5 | −12 |
| Сон < 6ч | −6 |
| Сон < 5ч | −12 |
| Отход ко сну позже +2ч от целевого | −5 |
| Не ответил на вечерний разбор | −8 |
| Игнор бота весь день | −10 (потом заморозка, см. §7) |
| 3 дня подряд выполнение < 40% | −20 (единоразово, не суммируется с дневным) |

### Щит (страховка)
**2 жетона в месяц.** Тратятся автоматически на самый крупный урон дня, если ты явно заявил причину («заболел», «форс-мажор», «семья»). Урон = 0, но событие записывается и видно в отчёте. Жетоны не копятся.

Смысл: убрать эффект «день уже испорчен → испорчу и неделю». Один плохой день не должен ломать месяц.

### При HP ≤ 30
Арвикс переходит в режим **восстановления**: план урезается до 3 задач в день, тон — собранный, не давящий, фокус на сон и один маленький результат в день. Штрафы действуют вполовину.

### При HP = 0
**Не потеря уровня.** Вместо этого: **Протокол Ноль** — 48 часов, в течение которых:
- План: сон, еда, движение, одна задача в день
- Никаких новых обязательств
- Обязательный разговор с Арвиксом об одной причине: что именно сломалось
- По выходу HP = 50, сезонные SP за эти дни = 0

## 4. Долг

Провалил задачу с `importance ≥ 4` — она **не исчезает**. Уходит в очередь долга:

- Долг видно на главном экране TWA отдельным красным блоком
- Пока в долге ≥ 2 задачи, Арвикс **блокирует** добавление новых необязательных дел (`sphere: social`, развлечения) — и прямо говорит, почему
- Долг можно закрыть или **списать**, но списание требует письменного обоснования, которое уходит в вечерний разбор к Analyst
- Долг старше 7 дней → −15 HP и обязательный разговор

Долг давит сильнее, чем цифра HP, потому что он мешает делать то, что хочется.

## 5. Время: бюджет недели вместо жёсткого 8/8/8

### Почему 8/8/8 с первого дня не работает
3-й курс колледжа + смены в пятницу, субботу и воскресенье. 8 часов продуктивной работы поверх этого **арифметически невозможны**. Первая же неделя даст −100 HP и вывод «система не работает», хотя не работала постановка задачи.

### Что вместо

**Неприкасаемое:** сон 7.5–8 ч, фиксированное окно отхода ко сну ±45 мин.

**Бюджет недели** (растёт по прогрессии):

| Период | Продуктивное время / нед | Из них глубокая работа |
|---|---|---|
| Месяц 1 | 26 ч | 8 ч |
| Месяц 2 | 30 ч | 10 ч |
| Месяц 3 | 34 ч | 12 ч |
| Месяц 4+ | +2 ч/мес, потолок 45 ч | потолок 18 ч |

Повышение происходит **только если предыдущий месяц закрыт ≥75%**. Не закрыт — бюджет держится, не растёт. Никогда не растёт «в наказание».

### Типы дней

| Тип | Когда | Профиль |
|---|---|---|
| **Учебный** | пн–чт | Колледж + 3-4 ч своего, из них 2 ч глубокой работы |
| **Рабочий** | пт–вс (смены) | Смена + 1.5-2 ч своего. Реалистичный минимум, не повод для стыда |
| **Глубокий** | 1 день/нед, обычно чт или вс | 5-6 ч глубокой работы одним блоком, минимум переключений |
| **Восстановительный** | 1 день/нед или по Burnout Guard | Сон, спорт, люди, ноль обязательных когнитивных задач |
| **Тихий** | 1 день/нед | Арвикс молчит, ты ведёшь сам (см. 00-VISION §5) |

Тип дня определяет шаблон, из которого Planner материализует задачи.

### 8/8/8 как горизонт
Цель остаётся, но как **направление прогрессии**, а не норма с первого дня. Отображается в TWA как «дистанция до 8/8/8»: текущее соотношение против целевого. Достигается примерно к месяцу 6-8 и только в дни без смены.

## 6. Burnout Guard — выключатель жёсткости

Детерминированный расчёт **в L0**, четыре режима. Режим подставляет тон-блок в промпт L1 — модель не выбирает его сама.

| Режим | Триггер (любой) | Поведение |
|---|---|---|
| 🟩 **НОРМА** | сон ≥7ч (3-дн. ср.), стресс ≤ сред., выполнение ≥60% | Стандартный Арвикс: требовательный, конкретный |
| 🟦 **ДАВЛЕНИЕ** | выполнение <50% **при** нормальном сне и стрессе | Максимальная жёсткость. Это лень, а не усталость — и он это знает |
| 🟨 **ЖЁЛТЫЙ** | сон <6ч 2 дня подряд · стресс высокий 2 дня · выполнение 20-40% | Нагрузка −30%, глубокая работа только утром, тон жёсткий но без давления, вопросы про причину |
| 🟥 **КРАСНЫЙ** | сон <5ч 3 дня · выполнение <20% неделю · HP ≤20 · ручной SOS | **Режим ментора выключен на уровне кода.** Штрафы заморожены. План: сон, еда, движение, один маленький результат. Тон — человеческий |

**Реализация — критично:** в 🟥 тон-блок «Гоггинс» физически не попадает в промпт, он заменяется блоком восстановления. Это не просьба к модели быть мягче — это другой промпт.

### Safety-контур (отдельно от Burnout Guard)

Если в сообщениях детектятся признаки серьёзного состояния (не «устал», а реальная беда):

1. Режим ментора отключается **насовсем**, до ручного включения в настройках TWA
2. Арвикс переходит на человеческий тон, без задач, без штрафов, без метрик
3. Прямо говорит: это не то, с чем справляется бот, и предлагает обратиться к человеку — специалисту или близкому
4. Событие пишется в лог с пометкой, чтобы Analyst не «разбирал эффективность» этого периода

Раз Арвикс претендует на роль психолога — без этого контура его писать нельзя. Это не опциональная фича.

## 7. Протокол игнора

Ты не отвечаешь боту. Сейчас в исходном ТЗ — стена штрафов, которая гарантирует, что ты не вернёшься.

| День | Что делает Арвикс |
|---|---|
| 1 | Обычные напоминания. Вечером: «Ты сегодня молчал. Что произошло?» |
| 2 | Одно сообщение утром, одно вечером. Тон жёстче. Штрафы идут |
| 3 | **Штрафы замораживаются.** Одно сообщение: «Три дня. Я не знаю, что происходит, и это хуже, чем провал. Напиши одно слово» |
| 4–7 | Одно сообщение в день, ноль давления, ноль метрик. Только «я здесь» |
| Возврат | **Протокол возвращения:** никакого разбора прошлого. Один вопрос «что случилось», один маленький шаг на сегодня, пересборка плана с нуля. Разбор пропущенного — только через 3 дня стабильной работы |

Смысл: система, которая встречает тебя стеной штрафов после срыва, удаляется. Система, которая встречает одним шагом, — переживает срыв.

## 8. Квоты по сферам — против распыления

Ты хочешь спорт, социум, отношения, путешествия, но не прыгать с дела на дело. Решение: **не ежедневные задачи, а недельные минимумы**.

| Сфера | Минимум/нед (старт) | Как считается |
|---|---|---|
| Спорт | 3 сессии | Задача sphere=sport, done |
| Социум | 2 живых контакта | Событие `social_contact` (можно отметить постфактум) |
| Новое | 1 раз | Задача с тегом `novelty` |
| Отдых без экрана | 3 × 60 мин | Отметка в TWA |
| Учёба (глубокая) | по бюджету | Часы deep_work в sphere=learning |

Механика:
- Квота **не дёргает** каждый день. Она видна полосками в TWA
- Со среды невыполненная квота начинает подсвечиваться
- В четверг Planner **сам вставляет** недостающее в свободные слоты
- В воскресенье незакрытая квота = −5 HP и вопрос в ретро
- Перевыполнение квоты не даёт XP — это защита от «убегания» в лёгкую сферу вместо трудной

## 9. Финансовый модуль

Банковских API для физлица нет. Строим на ручном вводе с минимальным трением.

### Ввод
- В TWA: **два тапа** — сумма (цифровая клавиатура) + категория (иконки). 4 секунды
- В чате: «потратил 1200 на еду» → L1 вызывает `log_expense`
- Повторяющиеся (подписки, транспорт, аренда) — заводятся один раз, списываются автоматически

### Модель
```yaml
Expense: { amount, currency, category, note, at, impulse: bool }
Budget:  { category, weekly_limit }
Goal:    { title, target_amount, saved_amount, deadline }
```

### Что делает Арвикс
- Недельный бюджет по категориям, предупреждение при 80%
- **Связь с целями:** «Эта трата — 4 дня отката от цели "ноутбук"». Вот это работает, а не голая цифра
- Флаг `impulse` ставишь сам в момент траты (одна кнопка). В вечернем разборе Арвикс разбирает импульсивные траты: что было триггером
- Недельный отчёт: топ-3 категории, дельта к прошлой неделе, прогресс по целям
- **Не даёт инвестиционных советов.** Только учёт, бюджет и связь с целями

### Границы
- Никаких банковских интеграций, никакого хранения номеров карт и счетов
- Доходы вводятся опционально, одной цифрой в месяц, только чтобы считать норму сбережений

## 10. Ежедневный цикл

| Время | Событие | Кто |
|---|---|---|
| **По пробуждению** | Синхронизация/ввод сна → расчёт Burnout Guard → Planner материализует день | L0 + L2 |
| **Утренний брифинг** | Оценка вчера (одна фраза), режим дня, 3 главные задачи, первый блок, квоты | L1 |
| **Весь день** | Напоминания T-5, старт блока, контроль, вопрос о выполнении, XP/HP | L0 |
| **Перерывы** | Предложение отдыха по Pomodoro-профилю блока, движение | L0 |
| **Середина дня** | Один проактивный чек-ин, если выполнение <40% к 15:00 | L1 |
| **22:30 Вечерний разбор** | Что сделано, честная оценка, 2 вопроса, импульсивные траты, план завтра | L2 → L1 |
| **За 30 мин до сна** | Напоминание об отбое, отключение задач | L0 |
| **Вс 20:00** | Недельное ретро: паттерны, квоты, бюджет, SP, коррекция плана | L2 → L1 |
| **1-е число** | Месячное ретро: цели, роадмапы, бюджет времени, Autonomy Score | L2 → L1 |

### Вечерний разбор — сердце системы

Именно он превращает день в данные. Структура:
1. Факты: X из Y задач, Z часов глубокой работы, сон, спорт
2. Одна честная оценка дня (не льстивая, не уничижительная)
3. **Два вопроса**, подобранных Analyst под конкретный день (не шаблонных)
4. Один вывод — что меняем завтра
5. Три задачи на завтра на подтверждение

Пропуск разбора = −8 HP. Это единственное, что нельзя пропускать.
