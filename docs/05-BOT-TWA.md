# 05 · Бот и Telegram Web App

## 1. Разделение ролей

| Канал | Для чего |
|---|---|
| **Чат бота** | Проактив, короткие решения кнопками, отчёты, разборы, разговор, голос, изменение плана |
| **TWA** | Сложный ввод (цели, шаблоны, план недели), визуализация, всё, что неудобно текстом |

Правило: **если это можно сказать одной фразой или кнопкой — это чат. Если это форма, таблица или график — это TWA.**

Правила чата:
- Решения — кнопками (inline), свободный текст — только где нужен смысл (отчёт, ответ на вопрос разбора)
- Каждое нажатие отвечает за < 1 с (`callback.answer()` сразу, работа — потом)
- После нажатия кнопки убираются или заменяются результатом — никаких «висящих» клавиатур
- Повторное нажатие — «Уже отмечено», не ошибка
- `callback_data` ≤ 64 байт: `act:<короткий код>:<id>` (UUID 36 символов + префикс укладываются)

## 2. Онбординг

### Проблема
Форма на 15 полей на первом экране = отвал. Страхи и слабости формой не собираются — человек пишет «прокрастинация» и уходит.

### Три стадии

**Стадия 1 — Ядро (3 минуты, форма в TWA).** Только то, без чего система не запустится:
1. Имя
2. Город и часовой пояс (пояс определяется по городу, можно поправить)
3. Целевое время отхода ко сну и подъёма
4. Занятость по дням недели: колледж / смена / свободно — сетка, или ссылка на календарь (ICS)
5. Одна главная цель на год: название, «зачем», метрика, срок
6. Безопасность: номер экстренной службы (дефолт `112`) и доверенный человек — можно пропустить, бот напомнит через неделю

→ **Система уже работает.** Создаются шаблоны дней из занятости, первый вечерний разбор предлагает план на завтра.

**Стадия 2 — Интервью (2 недели, 1 вопрос в день, вплетается в разбор).** Собирается только то, что меняет решения:

| Тема | Зачем | Куда |
|---|---|---|
| WOOP главной цели: что мешает? | План «если-то» | `goals.woop` |
| Когда лучше думается: утро/вечер | Расстановка глубоких слотов | `memory_facts` |
| Триггеры срывов: что, когда, после чего | Планы «если-то», протокол старта | `traits` |
| Что уже работает (хорошие привычки) | Не ломать работающее | `traits` |
| Языки: какие, уровень, цель | Модуль языков | `profile.languages` |
| Учёба: расписание, нагрузка, сессии | Шаблоны, сезонность нагрузки | `profile`, шаблоны |
| Вторая и третья цели года | Не больше 3 активных | `goals` |
| Страхи — **только если хочешь** | Иногда объясняют избегание | `traits(sensitive=true)` |

Размытый ответ уточняется одним вопросом: «"Прокрастинация" — это не ответ. В какой момент ты открываешь телефон вместо задачи?» Каждый вопрос можно пропустить.

**Стадия 3 — Постоянная.** Профиль никогда не «готов». Раз в месяц в месячном разборе: цели актуальны? триггер ещё срабатывает? план «если-то» работает?

## 3. Сценарии бота

### 3.1. Утренний чек-ин и брифинг
Формат — 02-MECHANICS §13.1–13.2. Всё — шаблоны L0, без модели.

### 3.2. Напоминание и старт (без ИИ)
```
T−5:   ⏱ Через 5 минут: Алгоритмы: графы · 90 мин · ДОЛГ
       Первый шаг: открыть задачу «Course Schedule» и выписать вершины
       [▶️ Начать сейчас] [⏳ +15 мин] [↪ Перенести]

T+0:   ▶️ Время: Алгоритмы: графы · 90 мин
       [▶️ Начал]

T+10:  Не начал. Что мешает?
       [Непонятно с чего начать] [Слишком большое]
       [Не хочу] [Нет сил] [Другое важнее]

конец: Алгоритмы: графы — результат?
       [✅ Сделано] [◐ Частично] [✖ Не сделано]
```
Реакции на причины — 02-MECHANICS §5.2.

### 3.3. Исход задачи
- `✅` при `confirm` → закрыто, коротко: «Закрыто. Следующий блок — 18:00, английский»
- `✅` при `report` → «Одной фразой: что из DoD сделано?» → FSM ждёт текст (≥ 15 символов)
- `◐` → «Что осталось?» → хвост в кандидаты на завтра
- `✖` → «Почему?» — кнопки причин → для `importance ≥ 4` сразу кнопки решения по долгу

### 3.4. Изменение плана из чата (модель сделки)
```
ЮЗЕР: Арвикс, я в 15:00 хочу погулять с подругой

[L1 → propose_schedule_change → L0: 3/7 выполнено, глубокая 0:40/2:00,
 конфликт с «Алгоритмы: графы» 15:00–16:30 (долг, 3-й день),
 свободный слот 20:00–21:30, решение по долгу до завтра 10:00]

АРВИКС: 3 из 7, глубокой работы 40 минут из двух часов. В 15:00 — долг по графам, третий день.
Если уходишь — переношу графы на 20:00. Если и вечером не выйдет, завтра к 10:00 по долгу
нужно будет решить: разбить или списать.
[Перенести на 20:00] [Оставить в 15:00] [Отменить блок]
```
Нажатие → L0 применяет → `task_rescheduled` → WS-пуш → TWA перерисовалась без перезагрузки.

### 3.5. Вечерний разбор
```
🌙 Разбор · четверг

Обязательства: 5 из 7 (71%). Глубокая работа 2ч10м из 2ч.
Не сделано: «Конспект YDKJS гл.3» — старт сорван (непонятно), «Зал» — нет сил.
Неделя: результаты 1/3, сон 6ч50м в среднем. Цепочка разборов: 12.

Вопрос: конспект сорвался второй раз с причиной «непонятно».
Что именно было непонятно — с чего начать или что считать готовым?
[ответ текстом] [Пропустить]

В inbox 3 записи. [Разобрать — 2 мин] [Завтра]

План на пятницу (рабочий день, смена 10–19):
1. 07:30 · Конспект YDKJS гл.3, первые 10 страниц · DoD: 5 тезисов своими словами в Obsidian
2. 20:00 · Английский · DoD: 20 карточек + 15 мин подкаста
[✅ Подтвердить] [✏️ Изменить]

Отбой в 23:30.
```

### 3.6. Недельное планирование (вс)
```
📅 Неделя 45 · итоги

Обязательства 68% · результаты недели 2 из 3 · глубокая работа 7ч из 8ч
Цели: Фронтенд — узлов роадмапа 1/1 ✅ · Английский — 140 карточек из 150, 3 сессии из 3
Сон 6ч55м, разброс отбоя ±50 мин · цепочка разборов 16

Что заметил фон:
1. Вторники снова провальные (2 из 6). Смена в понедельник вечером — данных 4 недели подряд.
2. Все сорванные старты — после 21:00.

Что меняем на следующей неделе? [ответ текстом]

Результаты недели 46 — предлагаю:
• Фронтенд: «Узел: Promise API — чекпоинт build: свой Promise.all» (~5 ч)
• Фронтенд: «Форма логина показывает ошибки сервера» (~4 ч)
• Английский: «150 карточек + 3 сессии + 1 письменный текст» (~5 ч)
Ёмкость: 14 ч из 22 ч свободных — запас есть.
[✅ Принять] [✏️ Изменить в TWA]
```

### 3.7. Учебный вопрос (Учитель)
```
ЮЗЕР: Как работает event loop в JS?

АРВИКС: Сначала сам. Три вещи: call stack, очередь задач, очередь микрозадач.

Источники:
- Твои заметки: JS/Async/event-loop.md — ты это конспектировал 4 месяца назад
- MDN: «The event loop» (первоисточник, ~15 мин)
- Узел роадмапа «JS: асинхронность» — там же видео на 35 мин

20 минут. Потом объясни мне своими словами — проверю. Застрянешь — /answer.

Все три источника пришли из инструментов (`search_notes`, `get_roadmap`); выдуманная ссылка была бы вырезана валидатором.

### 3.8. Помощь с делом (Помощник)
```
ЮЗЕР: Не понимаю, как подступиться к pet-проекту, он огромный

АРВИКС: Разобью на результаты, которые можно закончить за неделю. Предлагаю:
1. Страница списка задач с моковыми данными — DoD: рендерится, без бэкенда (~4 ч)
2. Форма добавления — DoD: задача появляется в списке, валидация пустого поля (~3 ч)
3. Сохранение в localStorage — DoD: после перезагрузки задачи на месте (~2 ч)
Первый в план этой недели?
[Да, все три в бэклог проекта] [Только первый на эту неделю] [Изменить]
```

### 3.9. Языковая сессия (Тренер)
```

### 3.10. Голос и inbox
- Голосовое → STT → текст обрабатывается как обычное сообщение. Если распознавание неуверенное — бот показывает распознанное: «🎙 Понял так: … Верно?»
- «Запиши: купить тетради» (голосом или текстом) → inbox
- Во время рабочего блока посторонний вопрос → «Записал в inbox, разберём вечером»

## 4. TWA — экраны

### 4.1. Сегодня (главный)
- Шапка: **индикатор режима цветом**, обязательства дня (x/y), цепочка разборов
- Следующий блок крупно: задача, DoD, первый шаг, кнопка [▶️ Начать] / [⏱ Фокус]
- Список задач дня: статус, свайп — исход, тап — детали (DoD, первый шаг, связь с целью)
- **Блок долга** (если есть) с кнопками решения
- Недельные результаты: 3 полоски прогресса
- Пустые слоты на сегодня — с кнопкой «заполнить»

### 4.2. План (неделя / день / шаблоны)
- Неделя списком по дням (v1), сетка 7×24 с перетаскиванием (v2, `dnd-kit`)
- Создание задачи: название, DoD, первый шаг, сфера, важность, длительность, deep work, цель/результат недели
- Шаблоны дней: слоты и занятые блоки, привязка к дням недели
- Занятость из календаря (ICS) — серым, только чтение
- **Всё синхронно с ботом по WebSocket**

### 4.3. Цели
- Дерево: мечта → цель года → цель квартала
- Карточка цели: зачем, метрика (прогресс), WOOP, опережающие показатели (факт/цель за неделю), связанный роадмап
- Результаты текущей недели и история закрытых

### 4.4. Обучение
- Роадмапы: граф/список узлов, источники, чекпоинты, оценка часов, процент
- Карточки: к повторению сегодня, удержание, кнопка сессии
- Языки: уровень, минуты ввода/практики за неделю, частые ошибки

### 4.5. Второй мозг (фаза 2)
- Дерево Obsidian, просмотр и правка Markdown, гибридный поиск, inbox, «Спросить Арвикса об этом файле»

### 4.6. Аналитика
- 7/30/90 дней: обязательства, стартуемость, сон, глубокая работа, движение vs поддержка
- Причины срывов: распределение по кодам и сферам
- Корреляции: сон ↔ выполнение, тип дня ↔ результат, время суток ↔ стартуемость
- Лента инсайтов фона с доказательствами (ссылки на события)
- Автономность (с месяца 2)

### 4.7. Настройки
- Профиль, часовой пояс, целевые сон/подъём, время разбора и ревью
- Бюджет времени, типы дней
- **Включатель режима ментора** (выключается safety-контуром, включается только здесь)
- Кризисные контакты, внешний свидетель
- Память: список фактов с правкой и удалением
- Интеграции: веб-поиск, MCP-серверы, календарь — статус, разрешения
- Устройства IoT: токены, статус
- Экспорт и бэкап

Убрано из v1.0: XP-полоса, HP, круговая диаграмма 8/8/8, сезоны, финансы (опциональный модуль).

## 5. Realtime-синхронизация

Требование «без обновления страницы» — жёсткое.

```
emit() → после commit → Redis pub/sub → WebSocket-хаб → все открытые клиенты TWA
```

- Публикация — **после** успешного commit (иначе клиент увидит то, что откатилось)
- TWA держит WS-соединение, переподключение с backoff, авторизация `initData` при подключении
- Сообщения: `{type: "task_updated", id}`, `{type: "day_changed", date}`, `{type: "mode_changed", mode}`
- TanStack Query: WS-сообщение инвалидирует нужный кэш → точечный ререндер
- Оптимистичные обновления: изменение рисуется сразу, откатывается при ошибке
- **Единый источник правды — Postgres.** Чат, TWA и Арвикс читают одно и то же

### Офлайн (PWA)
- Service Worker кэширует план на неделю и последние 30 дней метрик
- Офлайн-действия (исходы задач) копятся в IndexedDB и отправляются при возврате сети с исходным временем
- Это часть анти-зависимости: сервер лёг — план у тебя на руках
