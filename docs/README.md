# Arvix — спецификация

> Личный ИИ-ментор одного человека. Знает план и цели, сам напоминает, спрашивает результат,
> считает очки и режим нагрузки кодом, вечером проводит разбор, учит по сократовскому методу
> и постепенно становится не нужен. Живёт в Telegram и в Claude Code, данные — в твоём Obsidian.

**Ревизия 0.3 · 15.11.2026.** Описывает то, что реально работает в `arvix-claude/`
(плагин Claude Code + Telegram-бот + CLI на одном журнале событий, версия 0.3.0).
Что изменилось и почему — [09-DECISIONS.md](09-DECISIONS.md).

## Шесть правил, которые нельзя нарушать

1. **Всё, что можно сделать кодом, делается кодом.** Модель вызывается только там, где нужно
   понимание языка или суждение. XP, HP, долг, режим, напоминания, нагрузка, квоты — детерминированный
   Python (`arvix/rules.py`, `daily.py`, `load.py`, `telegram/scheduler.py`).
2. **Совет (L2) никогда не стоит в цепочке ответа.** Разбор и ретро идут по расписанию или по явной
   просьбе и пишут директивы в журнал. Ответ в чате — один вызов L1.
3. **Любое изменение состояния — событие в журнале.** Таблица `events` только дополняется (триггеры SQLite
   запрещают UPDATE и DELETE). Состояние — свёртка журнала; исправление — компенсирующее событие.
4. **Имена моделей — только в конфиге** (`arvix/defaults.toml`, `~/.config/arvix/config.toml`, секции `[roles.*]`).
   В коде их нет, это проверяется тестом.
5. **В 🟥 КРАСНОМ и при выключенном менторе жёсткие тон-блоки, жёсткие примеры и правило решений
   физически не попадают в промпт.** Не просьба к модели быть мягче — другой промпт. Тест: `tests/test_prompt_safety.py`.
6. **Один человек.** Бот отвечает только `owner_id`, остальных молча игнорирует. Никакой мультитенантности,
   регистрации, ролей, биллинга.

Седьмое, не правило, а фильтр: каждая новая фича отвечает на пять вопросов из [00-VISION.md §6](00-VISION.md#6-фильтр-псевдопродуктивности).
Одно «нет» — фича не делается.

## Словарь

| Термин | Значение |
|---|---|
| **L0 / L1 / L2** | Рефлексы (код, без ИИ) / Голос (один вызов модели на сообщение) / Совет (фоновый разбор и ретро) |
| **Голова** | Вызов `claude -p` по подписке Claude с собственным системным промптом и JSON-схемой ответа. Так Telegram-бот «думает» |
| **Журнал** | Таблица `events` в SQLite `~/.local/share/arvix/arvix.db` — единственный источник правды о прошлом |
| **Состояние** | `State` — свёртка журнала в памяти: профиль, задачи, дни, XP, HP, режим |
| **Дом Арвикса** | Папка `~/Arvix`, где Claude Code работает как Арвикс: стиль, хуки, строка состояния, доступ к хранилищу |
| **Хранилище** | Obsidian-vault владельца. Арвикс работает в его структуре, а не в отдельной папке |
| **Шаблон дня** | Блоки «время · длительность · название · сфера · важность» на день недели; из него утром создаются задачи |
| **Автонагрузка** | Коэффициенты объёма по каналам (глубокая работа, учёба, спорт, отдых), которые код пересматривает раз в неделю |
| **Burnout Guard** | Детерминированный выключатель жёсткости: 🟩 НОРМА · 🟦 ДАВЛЕНИЕ · 🟨 ЖЁЛТЫЙ · 🟥 КРАСНЫЙ |
| **Долг** | Проваленная задача важности 4–5. Не исчезает, пока не закрыта или не списана с обоснованием |
| **Директива** | Вывод совета с доказательствами (id событий), который L1 читает как факт |
| **Сократовский режим** | На учебный вопрос — направление, источник, время на самостоятельную работу; готовый ответ только по `/answer` |
| **Автономность** | Метрика анти-зависимости: выполнение в тихие дни против обычных + доля учебных вопросов без `/answer` |
